.NET SDKと実行コマンド

プロジェクトの作成、ビルド、実行とエラーの確認。

.NET 10 / C# 14

最初のコンソールプロジェクト

使用する環境は.NET 10 / C# 14です。SDKの細かな更新番号は固定して暗記せず、導入する時点の公式配布と対象環境を確認します。既に別のSDKがある場合も、dotnet --list-sdksで実際に使えるものを調べます。Runtimeだけではアプリ作成用の道具はそろいません。

ターミナルで入力するコマンド
dotnet --list-sdks
dotnet new console -n LearningScratch -f net10.0
cd LearningScratch
dotnet build
dotnet run

①SDKの一覧を見る、②ひな形のフォルダーを作る、③そのフォルダーへ移動する、④ソースから成果物を作る、⑤アプリを起動する、の順です。cdは操作対象のフォルダーを変えるコマンドで、C#の文法ではありません。ターミナルの現在位置に.csprojがあることを確認すると、「プロジェクトが見つからない」という失敗を減らせます。

Program.csを次の内容へ置き換えて保存します。同じ名前の変数を持つ例を何本も連結せず、一つの実験ごとにProgram.cs全体を入れ替えるか、別のプロジェクトを使います。

C# · 独立したコード例
int planned = 4;
int completed = 1;
int remaining = planned - completed;
Console.WriteLine($"残り{remaining}回");

期待される出力は残り3回です。まずplannedを4、completedを1にし、4-1を計算してremainingへ3を保存します。その後、値を文章へ組み込んで表示します。completedを2へ変更して保存し、もう一度起動すると、同じ式から残り2回となることを確認します。

変数・処理順の状態表

変数を箱の絵で覚えるだけでは、参照や非同期の段階で混乱します。まず「名前・型・現在の値・参照先」を分けます。数値なら値を、参照型なら実体にAやBという識別名を付けて記録します。

行動 planned completed remaining 説明
初期化後 4 1 未宣言 まだ差を計算していない
差を代入 4 1 3 この時点の結果を保存
completedを2へ 4 2 3 remainingを再計算しなければ3のまま
差を再計算 4 2 2 新しい状態から計算し直した

説明中の「未宣言」は、実際に格納される特別な値ではありません。その時点で追跡する変数がまだ導入されていないことを表す教材上の記号です。同様に参照図の「実体A」は、実際のメモリアドレスではありません。

失敗したときの確認順序

「動かない」を一つの問題として扱わず、失敗した段階を確定します。dotnet自体が見つからないなら、C#のif文を書き換えても解決しません。ビルドで止まっているなら、実行結果の推測を先にする必要はありません。

①コマンドが利用できるか、②正しいプロジェクトのフォルダーか、③ソースを保存したか、④最初のビルドエラーは何か、⑤起動時に例外が出たか、⑥正常終了したが期待値と違うか、の順に調べます。エラーが多数出たときは、最初の引用符や波かっこの欠落が後続へ連鎖していないかを見ます。

修正メモには「問題の入力」「期待値」「実際の結果」「最初に違った行」「変更理由」を残します。正解のコードだけを保存するより、次に同じ失敗が起きたときの調べ方を再利用できます。エラー調査の手引きでは、典型例をこの順序で調べます。
