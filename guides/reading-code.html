コード・構文・処理順の読み方

記号を丸暗記せず、宣言・式・文・呼び出し・状態変更の単位でC#を読む。

.NET 10 / C# 14

まず入力・処理・出力を探す

初めて見るコードは一文字ずつ暗記せず、何を受け取り、どう変え、何を外へ渡すかを探します。入力は利用者の文字列だけでなく、メソッドの引数やファイル、既存のオブジェクトの状態も含みます。出力は画面表示だけでなく、戻り値や保存、状態の変更も含みます。

C# · 独立したコード例
int price = 120;
int count = 3;
int total = price * count;
if (total >= 300)
{
    total -= 20;
}
Console.WriteLine(total);

このコードの入力となる値は120と3、処理は掛け算と割引判定、観察できる出力は340です。①priceを120、②countを3、③totalを360、④360>=300をtrue、⑤totalを340、⑥340を表示、となります。条件がtrueの場合にだけ⑤が行われることを、波かっこの範囲から読みます。

宣言・式・文を混ぜない

型は扱う値の規則、変数は名前と型を持つ値の場所です。宣言は名前を導入する記述です。式は評価すると値になるまとまりで、文は実行する処理の構文上のまとまりです。int total = price * count;では、int totalが変数を導入し、price * countが値を作る式、全体が宣言の文です。

部分 意味 読むときの問い
int 整数の型 どの種類の値を扱うか
total 変数名 何の値を保持するか
= 代入 右辺が作った値をどこへ保存するか
price * count 掛け算の式 その時点の二つの値はいくつか
; 文の終端 一つの処理がどこで終わるか

=は右辺と左辺の永続的な関係を登録する記号ではありません。priceが後で変わってもtotalは自動更新されず、必要なら同じ計算をもう一度代入します。==は比較で、結果はtrueかfalseです。型によって等しいと判定する規則が異なる点はLesson 14で扱います。

同じ記号でも置かれた場所で役割が違う

C#ではかっこや記号を複数の文脈で使います。記号の意味を一つだけで暗記すると、メソッドやジェネリックの段階で混乱します。外側の構文が何かを先に判断します。

記号 この形なら 意味
(...) Add(2,3) 呼び出し時の引数
(...) int Add(int a,int b) 定義時のパラメーター
(...) (price + fee) * count 式のまとまりを優先
{...} if (ok) { ... } 条件付きで行う文のブロック
{...} new List<int> { 1,2 } コレクションの初期値
[...] values[0] 添字で要素へアクセス
<...> List<int> 型を渡すジェネリックの型引数
< count < 10 大きさの比較
=> x => x * 2 ラムダ式の入力と処理
=> int Double(int x) => x * 2; 式によるメソッド本体
? string? name nullの可能性を示す型注釈
? : ok ? "可" : "不可" 条件によって値を選ぶ式

名前の後のかっこがあれば常に即実行、とも決めません。メソッド定義は呼ばれたときの処理を書く場所です。MapGetに渡すラムダも、登録された後の要求に対して呼ばれます。定義した時と呼び出す時を別の時間軸として読む習慣が、非同期やWeb APIへつながります。

メソッド呼び出しを往復として読む

次のコードでは、上から一行ずつ進む途中でAddの本体へ入り、戻ってきます。下に書かれたメソッド定義を、上から到達した順で勝手に実行するわけではありません。

C# · 独立したコード例
Console.WriteLine("開始");
int answer = Add(2, 3);
Console.WriteLine(answer);
Console.WriteLine("終了");

static int Add(int left, int right)
{
    Console.WriteLine("計算中");
    return left + right;
}

期待される出力は開始、計算中、5、終了です。呼び出しの引数2と3を計算し、leftとrightへ渡します。Addが計算中を表示し5を返すと、呼び出しの式全体が結果5として扱われ、answerへ保存されます。returnの後に同じメソッド内の処理は続かず、呼び出し元の続きへ戻ります。

評価順を安全な小さな式へ分ける

演算子の優先順位と、値をいつ読むかは関連しますが別の規則です。式が複雑で状態も変えると理解が難しくなります。学習中も実務でも、短くするためだけに副作用を詰めないようにします。副作用とは、変数や外部の状態を変更するなど、戻り値以外に影響を与えることです。

C# · 独立したコード例
int index = 0;
int first = index;
index++;
int second = index;
index++;
Console.WriteLine($"{first},{second},{index}");

期待される出力は0,1,2です。値を読む行と増やす行が分かれているため、どの時点で何を保存したかを追えます。複雑な式を調べるときも、まず等価な範囲で中間変数へ分け、変更前と結果が一致するかを確認します。短絡評価や例外の発生順を変える分割は等価ではない場合があるため、単純な見た目だけで書き換えません。

修正例：条件の範囲を読み違える

次の例は「60点以上なら合格と表示し、合格者数を増やす」という目的に合っていません。波かっこを省略したifは、直接続く一つの文だけを条件付きにします。

C# · 失敗を学ぶ例（そのまま起動しない）
int score = 50;
int passed = 0;
if (score >= 60)
    Console.WriteLine("合格");
    passed++;
Console.WriteLine(passed);

起きることはpassedが1になることです。インデントは人に見せる字下げであり、このコードの構文上の範囲を増やしません。修正位置はifの本体です。表示と加算を同じブロックへ入れます。

C# · 独立したコード例
int score = 50;
int passed = 0;
if (score >= 60)
{
    Console.WriteLine("合格");
    passed++;
}
Console.WriteLine(passed);

修正後の期待される出力は0です。scoreを60へ変えると合格と1になります。50だけでなく59・60・61を確認すると、ブロックの範囲と境界条件の両方を調べられます。防止策は、複数の意味のある処理を条件付きにするときにブロックを明示し、整形した見た目と構文を一致させることです。

コードを自分の言葉へ戻す演習

上の割引例で、price=80、count=3とした場合を追跡してください。入力は80と3、totalは240となり、240>=300がfalseなので割引は行わず240を表示します。ここでtotalの最終値だけ答えるのではなく、「条件がfalseだから、減算の文を通らない」と説明します。

標準の練習では、割引の条件を「合計300円以上かつ個数3以上」に変えます。論理積を表す&&を使い、両方を満たす場合だけtrueになります。応用では、この計算を引数priceとcount、戻り値totalのメソッドへ移します。入力の範囲検証はLesson 27で深めますが、今は受け取る値、変えるローカル、返す値を別々に示せれば十分です。
