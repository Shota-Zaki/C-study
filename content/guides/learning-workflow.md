## この教材で進める学習の一周

コードを読んで理解したつもりでも、手元で少し条件を変えると結果を説明できないことがあります。この教材では、**予想を言葉にし、値を追い、自分で変更したコードを確認する**ところまでを一周として扱います。正解を暗記するより、「どの行でどの値が変わるか」を説明できることを目標にします。

本編は8章32レッスンの順に進みます。各本編には既存の解説・例・演習・確認問題があり、対応する詳細解説では、処理を分解した図、状態表、失敗例と修正例を追加しています。詳細解説は単なる読み物ではなく、難しい演習へ進む前にコードの動きを確かめるための教材です。既に説明できる項目を何度も読む必要はありませんが、結果を説明できない項目を「分かった」にしないようにします。

```flow
① 本編の到達点を読む | 今回は何を説明できるようにするか決める
② 最小例の出力を予想 | まだ答えや解説を見ず、変数の表を作る
③ 詳細解説で処理を追う | 予想と異なる行を見つける
④ 演習の下書きを書く | 要件を自分の処理へ変換する
⑤ SDKでビルドして起動 | ブラウザーではなく自分の開発環境で確かめる
⑥ 間違いを分類して修正 | 原因・修正行・修正後の根拠を記録する
⑦ 境界を変えて再確認 | 空、0、上限、失敗などの別条件を試す
```

ブラウザーの下書き欄は文字を保存するためのものです。C#のコンパイラーや実行環境ではありません。下書きが保存できたこと、選択問題の回答が合ったこと、C#コードが正しいことは、それぞれ別の事実です。サイト内のコード出力は「期待される出力」として読み、手元で実測した結果と区別します。

## ブラウザーのページとC#のアプリは別物

教材はHTML・CSSなどの静的ファイルで表示されます。一方、学習するC#のアプリは、ソースファイルを.NET SDKでビルドして起動します。教材のページを再読み込みしても、自分のC#アプリは更新されません。反対にProgram.csを書き換えても、教材の解答が自動的に書き換わることはありません。

| 作業場所 | ここで行うこと | ここで確定しないこと |
|---|---|---|
| 教材ページ | 説明を読む、図や状態を追う | C#のビルド結果 |
| 下書き欄 | コードの文章を保存する | 文法の正しさ、プログラムの出力 |
| エディター | Program.csや設定を編集する | 保存していない変更のビルド |
| ターミナル | SDKコマンドでビルド・起動する | 出力が業務要件どおりかという判断 |
| 自分の確認表 | 期待値と観察結果を照合する | 試していない条件の正しさ |

ターミナルはコマンドを文字で入力して道具を操作する画面です。エディターは文章やソースを編集する道具です。SDKはアプリを作る道具一式です。どのエディターを選んでも、保存するソースとプロジェクトの考え方は共通です。

## 最初のコンソールプロジェクト

本教材の対象は.NET 10 / C# 14です。SDKの細かな更新番号は固定して暗記せず、導入する時点の公式配布と対象環境を確認します。既に別のSDKがある場合も、`dotnet --list-sdks`で実際に使えるものを調べます。Runtimeだけではアプリ作成用の道具はそろいません。

```powershell
dotnet --list-sdks
dotnet new console -n LearningScratch -f net10.0
cd LearningScratch
dotnet build
dotnet run
```

①SDKの一覧を見る、②ひな形のフォルダーを作る、③そのフォルダーへ移動する、④ソースから成果物を作る、⑤アプリを起動する、の順です。`cd`は操作対象のフォルダーを変えるコマンドで、C#の文法ではありません。ターミナルの現在位置に.csprojがあることを確認すると、「プロジェクトが見つからない」という失敗を減らせます。

`Program.cs`を次の内容へ置き換えて保存します。同じ名前の変数を持つ例を何本も連結せず、**一つの実験ごとにProgram.cs全体を入れ替えるか、別のプロジェクトを使います。**

```csharp
int planned = 4;
int completed = 1;
int remaining = planned - completed;
Console.WriteLine($"残り{remaining}回");
```

期待される出力は`残り3回`です。まずplannedを4、completedを1にし、4-1を計算してremainingへ3を保存します。その後、値を文章へ組み込んで表示します。completedを2へ変更して保存し、もう一度起動すると、同じ式から残り2回となることを確認します。

## コードの種類を見分ける

全てのコードブロックを同じ方法で起動することはできません。間違いを示す例や、一部分だけを示す例も教材に含まれます。パネルの種類と、直前の説明を必ず読みます。

| 表示する種類 | 意味 | 手元での扱い |
|---|---|---|
| C#・独立例 | コンソール用の一つのソース | 個別プロジェクトへ入れる |
| C#・入力あり | 端末から入力を待つ | 入力例を確認して手動起動 |
| C#・ファイル操作 | ディスクへ読み書きする | 練習専用フォルダーで、上書き先を確認 |
| C#・Web API | サーバーを起動する | Web SDKのプロジェクトと別の要求用端末を用意 |
| C#・部分例 | 前後の型や設定が必要 | 示された修正位置へ適用する |
| C#・失敗例 | 誤りを観察するためのコード | 原因を先に読み、危険な例は起動しない |
| C#・テスト例 | テスト用の型やパッケージが必要 | 対応するテストプロジェクトへ置く |
| 期待される出力 | 仕様やコードから予想する表示 | C#ソースへ貼り付けない |

無限ループや再帰が止まらない例は、誤りを理解するためのものです。一括起動の対象にしません。ファイル例は保存先のデータを上書きする場合があるため、仕事のフォルダーや重要なファイルを実験に使わないでください。

## 読むときに作る状態表

変数を箱の絵で覚えるだけでは、参照や非同期の段階で混乱します。まず「名前・型・現在の値・参照先」を分けます。数値なら値を、参照型なら実体にAやBという識別名を付けて記録します。

| 行動 | planned | completed | remaining | 説明 |
|---|---:|---:|---:|---|
| 初期化後 | 4 | 1 | 未宣言 | まだ差を計算していない |
| 差を代入 | 4 | 1 | 3 | この時点の結果を保存 |
| completedを2へ | 4 | 2 | 3 | remainingを再計算しなければ3のまま |
| 差を再計算 | 4 | 2 | 2 | 新しい状態から計算し直した |

説明中の「未宣言」は、実際に格納される特別な値ではありません。その時点で追跡する変数がまだ導入されていないことを表す教材上の記号です。同様に参照図の「実体A」は、実際のメモリアドレスではありません。

## 失敗したときの確認順序

「動かない」を一つの問題として扱わず、失敗した段階を確定します。`dotnet`自体が見つからないなら、C#のif文を書き換えても解決しません。ビルドで止まっているなら、実行結果の推測を先にする必要はありません。

①コマンドが利用できるか、②正しいプロジェクトのフォルダーか、③ソースを保存したか、④最初のビルドエラーは何か、⑤起動時に例外が出たか、⑥正常終了したが期待値と違うか、の順に調べます。エラーが多数出たときは、最初の引用符や波かっこの欠落が後続へ連鎖していないかを見ます。

修正メモには「問題の入力」「期待値」「実際の結果」「最初に違った行」「変更理由」を残します。正解のコードだけを保存するより、次に同じ失敗が起きたときの調べ方を再利用できます。[エラー調査の手引き](errors.html)では、典型例をこの順序で調べます。

## 次へ進むかを判断する

最小例の数値を変えても出力を予想できること、重要な行を自分の言葉で説明できること、失敗例をなぜ直せるか説明できることを確認します。選択問題で正解しただけでなく、誤答のどの前提が間違っているかを述べます。

本編の基礎演習で書き始められないときは、完成コードを一度写して終わらせず、「入力を用意する」「条件を確認する」「値を変える」「結果を返す」のどこが書けないかを分解します。詳細解説の同じ段階へ戻り、一箇所だけを自分で変更してから再挑戦します。学習時間やページ数ではなく、再現できる理解で進捗を判断します。
