04 文字列と入力の変換 — 詳細解説

文字列を数量として受け付ける条件。

.NET 10 / C# 14
本文・演習詳細解説
重要TryParseの成功と、業務上有効な値であることは別々に確認します。

図解：文字列を数量として受け付ける条件

文字列と数値の違い

画面で見える120は文字の並びとして表現されます。string text = "120";は文字列、int number = 120;は整数です。文字列の+は結合、整数の+は加算なので、"12" + "3"は"123"、12 + 3は15になります。入力を計算へ使うには、文字列の意味を読み取って数値へ変換する必要があります。この読み取りを解析、英語でparseと呼びます。

文字列はstring型の値です。C#のstringは内容をその場で変更できない性質を持ちます。この性質を不変と呼びます。TrimやReplaceは元の文字列の内容を書き換えるのではなく、結果となる文字列を返します。変数へ別の文字列を再代入することはできます。内容が不変であることと、変数へ再代入できないことは別です。

C# · 独立したコード例
string text = "  C#  ";
string cleaned = text.Trim();
Console.WriteLine($"[{text}]");
Console.WriteLine($"[{cleaned}]");
Console.WriteLine(text.Length);
Console.WriteLine(cleaned.Length);

期待される出力：

想定される出力 / データ
[  C#  ]
[C#]
6
2

Trim()は前後の空白を除いた結果を返します。[]を付けるのは、目に見えにくい空白の違いを観察するためです。Lengthは文字列の長さを読むプロパティで、UTF-16コード単位の数です。UTF-16は文字を数値単位で表現する方式で、絵文字などは見た目の一文字が複数単位になる場合があります。人が見た一文字を数えたい場合は単純なLengthと要件が一致するか検討します。

入力の三つの状態

Console.ReadLine()は通常、一行の入力を文字列で返します。何も入力せずにEnterを押すと空文字列""になります。入力の終わりを受け取った場合はnullを返し得ます。nullは文字列の内容ではなく「参照する値がない」ことを表す特別な値です。空文字、空白だけの文字列、nullは別々に考えます。

値 意味 数値へ変換できるか
"25" 二つの文字からなる入力 intの範囲なら変換できる
"" 長さ0の文字列 数字がなく失敗
" " 空白だけの文字列 数字がなく失敗
"abc" 数字でない文字列 失敗
null 入力終端などで文字列自体がない TryParseは失敗として扱える
"9999999999999999" 数字だがintの範囲外 失敗

この段階では、string?の?はnullの可能性を表す注釈、と理解してください。詳しいコンパイラーの検査はLesson 08で扱います。どんな入力も必ず数値になると仮定せず、成功と失敗の二つの流れを設計することが重要です。

TryParseの文法と処理順

C# · 独立したコード例
string? input = "25";
bool success = int.TryParse(input, out int quantity);
Console.WriteLine(success);
Console.WriteLine(quantity);

期待出力はTrue、次の行に25です。TryParseは成功したかをboolで返します。boolはtrueまたはfalseの二値を扱う型です。変換された整数はoutを付けた変数へ書き出されます。outはメソッドから呼び出し側へ値を書き戻す引数の形式で、Lesson 07で詳しく学びます。

入力を"abc"へ変えた場合、successはfalse、quantityは0になります。0は変換に成功した値とは限りません。"0"を渡した場合もquantityは0ですが、successはtrueです。そのため結果の数値だけで成功したかを判断してはいけません。

実用例：数量を受け取って合計する

次の例は対話入力を行います。入力を待つため、実行したターミナルに値を入力してEnterを押します。ブラウザー内の下書き欄ではこの処理は動きません。

C# · 入力を伴う例
Console.Write("数量を入力: ");
string? input = Console.ReadLine();
if (!int.TryParse(input, out int quantity))
{
    Console.WriteLine("整数を入力してください");
    return;
}
if (quantity < 1 || quantity > 100)
{
    Console.WriteLine("数量は1〜100で入力してください");
    return;
}
int total = quantity * 120;
Console.WriteLine($"合計: {total}円");

入力例は3、出力例は合計: 360円です。Console.Writeは改行せず表示します。!はtrue/falseを反転する演算子なので、最初のifは変換失敗時に入る分岐です。returnは現在の処理を終了して戻る文で、ここではアプリの入口を終えます。||は「どちらかがtrue」を表し、数量が範囲外なら計算へ進みません。これらの条件の読み方はLesson 05で扱います。

入力 変換結果 範囲の判定 最終結果
3 成功、quantity=3 範囲内 360円
abc 失敗、quantity=0 判定まで進まない 整数を入力してください
0 成功、quantity=0 範囲外 数量は1〜100で入力してください
100 成功、quantity=100 範囲内 12000円
101 成功、quantity=101 範囲外 数量は1〜100で入力してください

処理は「文字列として受け取る→整数にできるか→数量として妥当か→計算→表示」の順です。整数へ変換できることと注文として受け付けてよいことは別の検証です。この分離はWeb APIで受け取る入力にもそのまま役立ちます。

間違い：Parseを無条件に使う

C# · 失敗を学ぶ例（そのまま起動しない）
string input = "abc";
int quantity = int.Parse(input);
Console.WriteLine(quantity * 120);

これはコンパイルできても、整数として読めない文字列をParseへ渡すため実行時にFormatExceptionが起こります。範囲外の整数文字列ならOverflowExceptionになり得ます。例外は通常の次の文へ進めない異常を伝える仕組みです。入力文字列、例外の型、発生した行の三点を確認します。

修正位置は変換と、その結果を使う前の確認です。

C# · 独立したコード例
string input = "abc";
if (int.TryParse(input, out int quantity))
{
    Console.WriteLine(quantity * 120);
}
else
{
    Console.WriteLine("数量の形式が正しくありません");
}

期待出力は数量の形式が正しくありませんです。変換の失敗を普通に予想する入力ではTryParseが流れを明確にします。Parseが常に悪いのではなく、内部の保証されたデータを読み、失敗を異常として扱いたい場面などでは選択肢になります。利用場面の失敗の扱いを先に決めます。

間違い：Trimの結果を捨てる

C# · 独立したコード例
string name = "  Aoi  ";
name.Trim();
Console.WriteLine($"[{name}]");

このコードは正常な構文ですが、期待した空白除去は保存されません。期待される実際の出力は[ Aoi ]です。Trimの戻り値を受け取らず捨てているからです。修正位置はメソッド呼び出しの行です。

C# · 独立したコード例
string name = "  Aoi  ";
name = name.Trim();
Console.WriteLine($"[{name}]");

修正後の期待出力は[Aoi]です。変数nameが参照する文字列が変わり、元の文字列を直接削っているわけではありません。戻り値とは呼び出した処理が返す値です。文字列を操作するときは、そのメソッドが結果を返すのか、対象を変更するのかを確認します。

書式と文字の比較

表示のために数値を文字へ変えることと、入力を数値へ解析することは逆向きの処理です。$"{price:F2}"は小数二桁の見た目を作りますが、元の数値の型や値を文字列型へ変えるわけではありません。数値の小数点や桁区切りは環境のカルチャーに影響されるため、保存形式と人向けの表示を分けます。

識別子や固定のコマンドを比較するなら、文化的な並び順ではなく明示的な文字比較を選びます。string.Equals(input, "quit", StringComparison.OrdinalIgnoreCase)は大文字小文字を区別しないOrdinal比較です。Ordinalとは文字のコード上の値に基づく比較で、言語文化による単語の扱いに依存させたくない識別子に向きます。人名の並び順などは別の要件です。

操作 使うもの 選ぶ理由
文字と値を読みやすく組み合わせる 文字列補間 どこに何が入るか分かる
ユーザーの整数入力を調べる TryParse 成功と失敗を分けやすい
前後の空白を取り除く Trimの戻り値 元文字列が変わると誤認しない
大文字小文字を無視したコマンド比較 OrdinalIgnoreCase 比較規則を明示できる
大量に文字を追加する StringBuilderを検討 連続生成のコストを抑えられる場合がある

StringBuilderは変更可能な文字列組み立て用の部品です。短い表示文まで何でも置き換える必要はありません。まず読みやすいコードを作り、量や性能に問題がある場合に選びます。

段階別の練習

基礎課題は"12" + "3"と12 + 3の結果を説明することです。前者は文字列結合で123、後者は数値加算で15になります。出力だけが似ていても、保存している型と操作の意味が違います。

標準課題は、固定入力" 42 "をint.TryParseで読み、成功なら2倍を表示することです。期待出力は84です。通常の整数解析では前後の空白は許容されますが、入力全体の仕様として空白を禁止するなら追加検証が必要です。

C# · 独立したコード例
string input = " 42 ";
if (int.TryParse(input, out int value))
    Console.WriteLine(value * 2);
else
    Console.WriteLine("変換できません");

応用課題は、数量入力例の仕様へ「前後の空白は許可、範囲は1〜100、abcと0で別のメッセージ」を保ったまま、単価を変数へ分けることです。計算行だけでなく、入力チェックの順序が変わっていないか確認します。よくある間違いは、TryParseのboolを確認せずquantity=0を利用し、形式エラーも範囲エラーとして表示してしまうことです。

境界値・比較

境界・比較例：識別子の前後空白と大文字小文字

Trimは前後の空白を除いた文字列を返します。OrdinalIgnoreCaseはこのコマンド名を大文字小文字を区別せず比較します。

C# · Program.cs
string input = "  SAVE  ";
string command = input.Trim();
bool isSave = string.Equals(command, "save", StringComparison.OrdinalIgnoreCase);
Console.WriteLine(command);
Console.WriteLine(isSave);

想定出力

SAVE
True
