08 nullを型と分岐で扱う — 詳細解説

未指定・空文字・空白の違い。

.NET 10 / C# 14
本文・演習詳細解説
重要null、空文字、空白だけの文字列は異なります。必要な規則に合う判定方法を選びます。

表示名が未指定なのか、空文字なのか、空白だけなのかを区別します。その違いを確認してから、nullを持つ可能性がある型と、安全に値を読む方法を学びます。

null・空文字・0の違い

参照型の変数はオブジェクトをたどるための参照を保持します。オブジェクトとは実行中に存在する型の実体です。stringの文字列も参照型です。nullはその参照がどの実体も指していないことを表します。""は長さ0の文字列という実体があり、"null"は四文字の普通の文字列です。

nullを無視すると、存在しない相手に対してLengthを読んだりメソッドを呼んだりして、NullReferenceExceptionが起こります。これはコンパイル後の実行時に起こる例外です。一方、nullable reference typesは、nullの可能性をソース上の型へ注釈し、危険な使い方をコンパイラーが警告する機能です。実行時に新しい別の参照型を作る機能ではありません。

.csprojで<Nullable>enable</Nullable>を有効にして学習します。警告は実行を必ず止めるものではなく、設定によっては警告があってもビルドできます。null非許容と書けば外部データから絶対にnullが来ない、という実行時の保証にはなりません。

string?とint?は同じ仕組みではない

string?は参照型のnull許容注釈です。stringとstring?は実行時には同じ型で、コンパイラーが意図と経路を検査します。int?はNullable<int>という値型で、整数値と値が存在するかという情報を扱います。普通のintはnullを保持できません。

記述 何を表すか 主な扱い方
string nullでないことを意図する参照 null警告を減らして契約を明示
string? nullを含み得る参照 使用前に経路や代替値を決める
int 整数値 0も有効な整数
int? 値なし、または整数 HasValueやパターン、??を使う

0を「値がない」の代わりに使うと、無料価格0や点数0と区別できないことがあります。int?なら値なしと0を別の状態として保持できます。ただしnullを認めればよいのではなく、その状態が業務として何を意味するかも定義します。

int?とstring?は、どちらも「nullの可能性」を表しますが、同じ新しい型の作り方ではありません。

string?の注釈だけで実行時のnullを防げるわけではありません。型の注釈と、実際の入力確認を組み合わせます。

最小例：分岐で安全な経路を作る

C# · 独立したコード例
#nullable enable
string? name = null;
if (name is null)
{
    Console.WriteLine("名前がありません");
}
else
{
    Console.WriteLine(name.Length);
}

期待出力は名前がありませんです。is nullはnullのパターン判定です。else側ではnameがnullでないことが分かるため、コンパイラーもその経路のLengthアクセスを安全と判断できます。このように各経路でnullの可能性を追うことをフロー解析と呼びます。

入力 判定 通る経路 出力
null true 最初のブロック 名前がありません
"" false else 0
"Aoi" false else 3

同じ変数でも、ifの前とelseの中では分かっている情報が違います。いったんnullを除外しても、後でその変数へnullを再代入すれば状況は変わります。古い確認を根拠に、その後すべてのアクセスが安全だとは判断しません。

?. と ?? を別々に読む

null条件演算子?.は、左側がnullなら右のメンバーへアクセスせずnullを返します。null合体演算子??は、左の値がnullの場合に右の代替値を使います。この二つを組み合わせると、値なしの扱いを小さな式で書けます。

C# · 独立したコード例
string? name = null;
int? length = name?.Length;
int displayLength = length ?? 0;
string displayName = name ?? "未登録";
Console.WriteLine(length.HasValue);
Console.WriteLine(displayLength);
Console.WriteLine(displayName);

期待出力はFalse、0、未登録です。通常のLengthはintですが、?.で呼ばれなかった場合も表すため、この式の結果はint?になります。HasValueはNullable値型に実際の値があるかを読むプロパティです。

時点 name length displayLength
初期化 null 未宣言 未宣言
name?.Length null null 未宣言
length ?? 0 null nullのまま 0

??は左の変数を自動的に書き換えません。代入もしたい場合の??=は別の演算子です。たとえばname ??= "未登録";ならnameがnullのときだけ代替値を代入します。

空文字を「未登録」にしたいなら??だけでは足りません。""はnullではないのでそのまま返ります。string.IsNullOrWhiteSpace(name)はnull・空文字・空白だけをまとめて調べるメソッドです。これらを同じ扱いにするかどうかは入力仕様で決めます。

本文の実例との対応：未指定・空文字・空白の違い

次の図は本文の実例「表示名の既定値」を使った補助例です。この節のコードとは変数や入力値が異なるため、処理の対応に注目します。

境界値・比較

境界・比較例：null条件演算子と既定値

?.は対象がnullなら後続のLengthへアクセスしません。空文字は存在する文字列なのでLengthの0が返ります。

C# · Program.cs
string? first = null;
string? second = "";
Console.WriteLine(first?.Length ?? -1);
Console.WriteLine(second?.Length ?? -1);

想定出力

-1
0
サンプル一式 Program.cs

実用例：表示名の正規化

正規化とは、複数の表記を扱いやすい形へ揃えることです。この例では前後の空白を除き、null・空文字・空白だけは匿名へ統一します。元の入力を壊さず、表示用の結果を戻します。

C# · 独立したコード例
string?[] inputs = { null, "", "   ", "  Aoi  " };
foreach (string? input in inputs)
{
    Console.WriteLine(GetDisplayName(input));
}

static string GetDisplayName(string? input)
{
    if (string.IsNullOrWhiteSpace(input))
    {
        return "匿名";
    }
    return input.Trim();
}

期待出力は匿名、匿名、匿名、Aoiです。string?[]はnullになり得る文字列を要素に持つ配列です。メソッドの戻り値はstringなので、このメソッドはnullではなく表示可能な文字列を返す契約になります。引数はstring?なので、呼び出し側は値がない場合も渡せます。

判定を先に行ってreturnする書き方をガード節と呼びます。不正や特別な条件を早めに処理して戻る方法です。残りの本体では有効な入力に集中できます。標準ライブラリのnull解析用の注釈により、IsNullOrWhiteSpaceがfalseだった経路のinputはnullでないと解析できます。

間違い：!で問題を解決したつもりになる

C# · 失敗を学ぶ例（そのまま起動しない）
#nullable enable
string? name = null;
Console.WriteLine(name!.Length);

!はここではnull抑制演算子で、コンパイラーへnullではないと扱うよう伝えます。値を生成したり、nullを空文字へ変換したり、実行時の検査を追加したりしません。そのため上のコードは警告を抑えられても、実行時にはNullReferenceExceptionが起こります。

修正位置はLengthを読む前の処理です。値なしを0文字として表示する仕様なら次のように書きます。

C# · 独立したコード例
string? name = null;
Console.WriteLine(name?.Length ?? 0);

期待出力は0です。名前が必須の処理なら0を補うのではなく、入力を要求するか、呼び出しを拒否する必要があります。正しい修正はnullを隠すことではなく、「ない場合に何をすべきか」を決めることです。

name!はコンパイラーへのnull警告の抑制です。入力値を埋めたり、存在を確認したりする処理ではありません。

外部入力がnullになり得るなら、分岐・代替値・入力拒否のどれかを仕様として選びます。警告が消えたことと安全になったことを区別します。

間違い：Nullable値型のValueを無条件に読む

C# · 失敗を学ぶ例（そのまま起動しない）
int? score = null;
Console.WriteLine(score.Value);

これは参照がnullである例とは違い、値を持たないNullableからValueを取得しようとしています。実行時には通常InvalidOperationExceptionになります。例外の型まで同じだと決めつけず、対象が参照型なのかNullable値型なのかを確認します。

C# · 独立したコード例
int? score = null;
if (score is int actualScore)
{
    Console.WriteLine(actualScore);
}
else
{
    Console.WriteLine("未受験");
}

期待出力は未受験です。is int actualScoreは実際の整数値があるときに、その値をactualScoreへ受け取るパターンです。score=0なら0を表示できるので、未受験と0点を区別できます。別解はHasValueを確認してからValueを読む方法です。

int? scoreには、整数かnullのどちらかが入ります。score.Valueは常に安全ではありません。

代替値でよければscore ?? -1などの形もあります。欠損を0と同一視してよいかは、データの意味によって決めます。

null対策を選ぶ基準

方法 選ぶ場面 避けたい使い方
ガード節 値なしでは本体を進められない 何も説明せず黙って失敗を隠す
?. 値があればアクセスする 必須処理の未実行を見逃す
?? 適切な代替値が決まっている 値なしと本当の0を不用意に同一視
nullable注釈 APIの契約を示す 外部データの実行時検証の代用
! 他の仕組みで非nullを保証でき、その根拠がある 警告を一括で消すために乱用

GCは不要なオブジェクトのメモリを再利用可能にする仕組みです。変数へnullを代入すると、その変数からは元の実体へ到達できなくなります。しかし別の参照が残っていれば、実体はそこから利用できます。nullを代入した瞬間にオブジェクトが必ず削除されるわけではありません。

段階別の練習

基礎課題はnull・空文字・"0"を区別することです。name?.Length ?? -1なら順に-1・0・1になります。-1はこの練習で値なしを識別する表示上の値であり、文字列の実際の長さではありません。

標準課題は未受験を表すint? scoreから表示用の文字列を返すことです。nullなら未受験、0なら0点、80なら80点が要件です。

C# · 独立したコード例
Console.WriteLine(FormatScore(null));
Console.WriteLine(FormatScore(0));
Console.WriteLine(FormatScore(80));

static string FormatScore(int? score)
{
    return score is int value ? $"{value}点" : "未受験";
}

応用課題は表示名の正規化へ最大20文字という教材上の制約を加えることです。この段階ではLengthによるUTF-16コード単位数を基準とする、と要件へ明示します。null確認前にLengthを読むと本末転倒です。まず正規化し、返された非nullの文字列へ長さの規則を適用します。ユーザーが見る文字数で制限する場合は別の文字の数え方を検討します。
