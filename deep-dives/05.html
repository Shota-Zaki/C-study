05 条件分岐とパターン — 詳細解説

送料の分岐。

.NET 10 / C# 14
本文・演習詳細解説
重要if / else ifは最初に一致した分岐だけを実行します。条件の順番も動作の一部です。

図解：送料の分岐

条件式の評価と分岐先

条件分岐は、条件式の結果に応じて実行する処理を選ぶ仕組みです。条件式はtrueまたはfalseの値を作る式です。たとえばstock > 0は在庫が正ならtrueになります。分岐がなければ、在庫0でも購入処理へ進むなど、異なる状態へ同じ処理を適用してしまいます。

boolはtrueとfalseを扱う型です。「0なら偽、その他なら真」という暗黙の読み替えをC#のifは行いません。if (stock)ではなく、if (stock > 0)のように判断を明示します。何を真とするのかを条件式へ書くことで、境界の値や業務ルールをレビューできます。

if・else if・elseが連なっている場合は、上から条件を調べ、最初にtrueになった一つの枝へ進みます。一方、独立したifを複数書くと、それぞれの条件を別々に検査します。この違いを理解しないと、複数の料金区分を表示したり、同じ値へ二重に割引したりする問題が起こります。

文法と最小例

C# · 独立したコード例
int score = 80;
if (score >= 80)
{
    Console.WriteLine("合格・優秀");
}
else if (score >= 60)
{
    Console.WriteLine("合格");
}
else
{
    Console.WriteLine("再挑戦");
}
Console.WriteLine("判定終了");

期待出力は「合格・優秀」、次の行に「判定終了」です。かっこ内が条件式、{}内が条件に対応する文のまとまりです。このまとまりをブロックと呼びます。今回は80が最初の条件を満たすため、60以上かどうかの二つ目の条件は評価しません。

段階 調べること 結果 次の動き
① scoreを80で初期化 score=80 最初のifへ
② 80 >= 80 true 最初のブロックへ
③ 表示 合格・優秀 else ifとelseを飛ばす
④ 分岐の後の文 判定終了 終了

分岐の内部ではscoreを書き換えていないため、処理の前後でscoreは80のままです。「条件を調べること」と「状態を変更すること」を分けて読むと追跡しやすくなります。コンパイラーはブロックや条件をIL上の制御の流れへ変換し、実行時には選ばれた経路の処理が進みます。ソースの全ブロックを毎回実行してから不要な結果を捨てるわけではありません。

境界値から設計する

境界値とは、結果が切り替わる付近の値です。上の例なら59・60・79・80が重要です。70と90だけを試しても、>=を>と書いてしまう間違いには気付けません。条件を文章へ戻し、「80点を含むか」を明示します。

条件 数学的な範囲 典型的な確認値
score >= 80 80以上 79、80、81
score > 80 80を除く、それより大きい値 80、81
score >= 60 && score < 80 60以上80未満 59、60、79、80
`score < 0 score > 100`

&&は両方がtrueの場合だけtrue、||は少なくとも一方がtrueならtrueです。!はtrueとfalseを反転します。=は代入、==は等しいかの比較です。役割の似ていない記号でも一文字しか違わないため、エラーを調べるときは意図を日本語へ戻します。

短絡評価は右側を実行しない場合がある

短絡評価とは、左側だけで結論が決まった場合に右側を評価しないことです。&&は左がfalseなら、||は左がtrueなら右を評価しません。これは速度だけでなく、安全に値へアクセスする順序に関わります。

C# · 独立したコード例
int value = 0;
bool canCalculate = value != 0 && 10 / value > 1;
Console.WriteLine(canCalculate);

期待出力はFalseです。左のvalue != 0がfalseなので10 / valueは実行されず、整数の0除算を避けられます。右側が先に評価されるように式を並べ替えると安全ではありません。

boolの&や|は短絡せず両側を評価します。論理条件を書きたいのに記号を一つ落とすと、避けたい処理まで実行される場合があります。副作用とは、値を返すだけでなく外側の状態を書き換えることです。条件式の中で代入やカウンター更新を多用すると、評価を省略したときの状態も変わるので、まずは判定と更新を分けます。

実用例：入力検証と価格区分

C# · 独立したコード例
int age = 12;
if (age < 0 || age > 120)
{
    Console.WriteLine("年齢の範囲を確認してください");
    return;
}
int fee;
if (age < 6)
{
    fee = 0;
}
else if (age < 18)
{
    fee = 500;
}
else
{
    fee = 1000;
}
Console.WriteLine($"料金: {fee}円");

期待出力は料金: 500円です。まず入力の範囲を検証し、不正なら終了します。その後に有効な値を区分します。feeは宣言時には未代入ですが、後のif/else if/elseのすべての経路で代入されるため、その後に読むことができます。elseをなくしてどの条件にも入らない経路が残ると、未代入の読み取りをコンパイラーが指摘します。

この例の年齢範囲・料金区分は教材の仕様です。現実の料金ルールとして一般化しません。実務では同じintでも何を表すか、どの範囲なら有効かを仕様として決めます。入力の妥当性と料金の計算を分けると、Lesson 27の責務の分離にもつながります。

間違い：広い条件を先に書く

C# · 独立したコード例
int score = 90;
if (score >= 60)
    Console.WriteLine("通常合格");
else if (score >= 80)
    Console.WriteLine("優秀合格");

これはコンパイルエラーではありませんが、90点で通常合格になります。80以上の値は必ず60以上なので、最初の分岐で捕まります。二つ目の条件が役立たないのは、記号の問題ではなく条件の範囲の包含関係が原因です。

修正位置は条件の並びです。

C# · 独立したコード例
int score = 90;
if (score >= 80)
    Console.WriteLine("優秀合格");
else if (score >= 60)
    Console.WriteLine("通常合格");
else
    Console.WriteLine("再挑戦");

期待出力は優秀合格です。確認するときは60・80だけでなく59・79も使います。条件を修正する前に表へ範囲を書けば、順序によって到達できない枝がないかを見つけやすくなります。

switch式とパターンを読む

パターンは値の形や条件を照合する表現です。関係パターンなら>= 80、型パターンなら「この型である」、プロパティパターンなら「このプロパティの状態である」を調べられます。いまは数値を範囲へ分類する例から始めます。

C# · 独立したコード例
int score = 75;
string label = score switch
{
    < 0 or > 100 => "範囲外",
    >= 80 => "優秀",
    >= 60 => "合格",
    _ => "再挑戦"
};
Console.WriteLine(label);

期待出力は合格です。score switchはscoreを照合対象にし、各行を上から調べます。=>の右側はその枝が返す値、_はそれまで一致しなかったすべてを受けるパターンです。orはパターン同士を組み合わせます。switch式は値を返すため、結果を変数へ保存できます。

選択肢 適する場面 判断の理由
if 条件ごとに複数の処理を行う 手順を明示しやすい
switch式 一つの対象から値を選ぶ 変換表として読める
条件演算子?: 小さな二択の値 入れ子が深いと読みにくい
独立した複数のif 複数の条件を同時に適用する 一つだけ選ぶならelse ifと区別

段階別の練習

基礎課題は、点数79・80・81を最小例へ入れて結果を説明することです。79は合格、80と81は合格・優秀です。>=の等号が境界を含めています。

標準課題は、点数の範囲0〜100の検証を最小例へ追加することです。不正入力-1と101は範囲外とし、その後の成績判定へ進めないようにします。ヒントは最初に範囲外を検査してreturnすることです。別解は外側のif/elseで有効な値だけ判定する方法です。

応用課題は、年齢料金へ会員割引100円を追加し、無料区分は0円のままにすることです。bool isMember = true;は会員かどうかの状態を表します。料金を先に区分し、if (isMember && fee >= 100) fee -= 100;と適用します。入力12歳・会員なら400円、5歳・会員なら0円です。割引を各枝へ重複記述する別解は修正漏れを生みやすいため、共通処理へ分けられるかを考えます。

境界値・比較

境界・比較例：境界値を表にする

>=と>ではちょうど5000円の扱いが変わります。境界の直前・境界・直後をセットで確認します。

C# · Program.cs
foreach (int subtotal in new[] { 4999, 5000, 5001 })
{
    int shipping = subtotal >= 5000 ? 0 : 600;
    Console.WriteLine($"{subtotal}円 → 送料{shipping}円");
}

想定出力

4999円 → 送料600円
5000円 → 送料0円
5001円 → 送料0円
