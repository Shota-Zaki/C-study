コレクションを選ぶ前に、必要な操作を決める

コレクションは複数の要素をまとめて扱う部品です。配列は長さが固定、Listは順序付きで追加・削除ができ、Dictionaryはキーから値を探すことに向いています。「複数だから何でもList」と決めるのではなく、順序・重複・検索方法・更新方法を先に考えます。

ジェネリックは、扱う型を引数として受け取れる型やメソッドの仕組みです。List<int>はintを要素とするList、List<string>はstringを要素とするListです。Tはその型のための仮の名前です。要素の型を保てるため、取り出すたびにobjectから変換したり、違う型を入れた誤りを実行時まで持ち越したりしにくくなります。

Listの状態を一操作ずつ追う

C# · 独立したコード例
var numbers = new List<int> { 1, 2, 3 };
numbers.Add(4);
numbers.Remove(2);
numbers[0] = 10;
Console.WriteLine(string.Join(",", numbers));
Console.WriteLine(numbers.Count);

期待出力は10,3,4、3です。Addは末尾へ追加、Removeは一致する最初の要素を削除、[0]は先頭要素へのアクセスです。Countは現在入っている要素数です。

操作 前の状態 後の状態 Count
初期化 なし [1,2,3] 3
Add(4) [1,2,3] [1,2,3,4] 4
Remove(2) [1,2,3,4] [1,3,4] 3
[0]=10 [1,3,4] [10,3,4] 3

Listは通常、内部の配列に要素を保存します。Capacityは内部で確保している要素の収納能力、Countは現在入っている要素数です。Capacityを100にしても、要素が100個あるとは限りません。追加時に容量が足りなければ、より大きな領域へ要素をコピーする場合があります。具体的な容量増加の数値へ依存したコードは書きません。

末尾追加は通常効率的ですが、途中のInsertやRemoveAtでは後ろの要素をずらす処理が必要です。要素が少なければ読みやすさを優先し、非常に大量のデータでは操作回数や計算量を測ります。計算量とは要素数に応じて必要な処理がどう増えるかという見方です。

Dictionary：位置ではなくキーで探す

キーは値を取り出すための識別子です。商品コードから在庫を探すなら、何番目の商品かを覚えるよりDictionaryが自然です。通常、同じキーを二つ同時に登録できません。何を「同じキー」とするかには等値性と比較規則が関係します。

C# · 独立したコード例
var stock = new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase)
{
    ["PEN"] = 5,
    ["BOOK"] = 2
};
stock["PEN"] = stock["PEN"] - 1;
if (stock.TryGetValue("pen", out int quantity))
{
    Console.WriteLine(quantity);
}
Console.WriteLine(stock.TryGetValue("CLIP", out _));

期待出力は4、Falseです。Dictionary<string,int>はキーがstring、値がintの型です。OrdinalIgnoreCaseはこの教材のコード識別子を大文字小文字を区別せず比較する指定です。out _は取得した値を使わず、成功したかだけ受け取る書き方です。

時点 PEN BOOK CLIP
初期化 5 2 登録なし
PENを減らす 4 2 登録なし
penで検索 4を取得 変化なし 登録なし
CLIPで検索 変化なし 変化なし false、追加はしない

Dictionaryはハッシュを利用して候補を探し、等値性の比較でキーを識別します。ハッシュコードが同じだけで同じキーと決めるわけではありません。列挙順を表示仕様の保証として使わず、順序が必要なら明示的に並べ替えます。

実用例：コマンドの件数を数える

C# · 独立したコード例
string[] commands = { "save", "load", "save", "SAVE", "load" };
var counts = new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase);
foreach (string command in commands)
{
    counts.TryGetValue(command, out int current);
    counts[command] = current + 1;
}
Console.WriteLine($"save={counts["save"]}");
Console.WriteLine($"load={counts["load"]}");

期待出力はsave=3、load=2です。初回はキーがないためTryGetValueはfalseを返し、currentはintの既定値0になります。この例では「未登録なら0回」という仕様なので、その0を利用して1を設定して構いません。変換失敗時の0を無条件で使う例とは、0の意味が明確な点が違います。

最初のsaveで1、loadで1、二度目のsaveで2、SAVEでも同じキーとして3、最後のloadで2になります。インデクサーcounts[command] = ...は、キーがなければ追加し、既存なら値を更新します。Addは重複キーを拒否する操作なので、どちらを選ぶかで不正入力の検出方法が変わります。

IEnumerable・ICollection・Listを区別する

インターフェイスは利用できる操作の契約です。IEnumerable<T>は順に要素を取り出せることを表します。CountやAddが必ずある契約ではありません。ICollection<T>はCountや追加・削除などの操作を持ちますが、実装によっては読み取り専用で、変更操作が許されない場合があります。Listはそれらを実装する具体的なコレクションです。

型 主に表すもの 選択場面 注意
T[] 長さ固定の具体的配列 要素数が決まる結果 要素は変更可能
List<T> 変更可能な順序付きコレクション 追加・削除しながら作るデータ CapacityとCountは別
Dictionary<K,V> キーと値の対応 コードやIDで検索 重複キーの扱いを決める
IEnumerable<T> 順に列挙できる契約 読み取り処理の入力 遅延処理や一度しか使えない列挙もあり得る
ICollection<T> 件数・変更操作などの契約 その能力が必要 IsReadOnlyを含む実装の条件に注意
IReadOnlyList<T> 件数と位置による読み取り契約 変更を要求しない利用側 実体そのものの不変性は保証しない

後のLINQは主にIEnumerableを入力として処理をつなぎます。Listを渡しても、IEnumerableとして受けるメソッドからはList固有のAddを契約として要求しません。利用側が本当に必要な能力だけを受け取る設計へつながります。

自分でジェネリックな型を作る

C# · 独立したコード例
var numberBox = new Box<int>(10);
var nameBox = new Box<string>("Aoi");
Console.WriteLine(numberBox.Value);
Console.WriteLine(nameBox.Value);

public class Box<T>
{
    public T Value { get; }
    public Box(T value)
    {
        Value = value;
    }
}

期待出力は10、Aoiです。Tは実際に使う型へ置き換わる型パラメーターです。実行時には構築されたジェネリック型の情報も扱われます。値型と参照型でJITがコードを共有・特殊化する方法は異なる場合がありますが、学習の中心は型安全な再利用です。

Tに何の制約もなければ、Tが必ずLengthやPriceを持つとは言えません。where T : IHasPriceのような制約は、Tが満たす能力を指定する仕組みです。必要な操作をコンパイラーへ示せます。ただし、まだ必要でない拡張を見越して複雑な制約を増やすのではなく、具体的な重複と契約から導きます。

間違い：列挙中にListを追加・削除する

C# · 失敗を学ぶ例（そのまま起動しない）
var values = new List<int> { 1, 2, 3, 4 };
foreach (int value in values)
{
    if (value % 2 == 0) values.Remove(value);
}

Listをforeachで列挙している途中に構造を変更すると、通常は列挙子が変更を検出してInvalidOperationExceptionになります。削除によって位置がずれることもあり、どの要素が次かという前提を壊すからです。更新箇所と列挙対象が同じ実体かを確認します。

修正位置は削除方法です。

C# · 独立したコード例
var values = new List<int> { 1, 2, 3, 4 };
values.RemoveAll(value => value % 2 == 0);
Console.WriteLine(string.Join(",", values));

期待出力は1,3です。value => ...は条件を判定する処理を値として渡すラムダ式です。Lesson 17で詳しく扱います。ここではRemoveAllに「削除する要素の条件」を渡しています。別解は後ろから位置を調べてRemoveAtする方法で、削除後のずれが未処理部分へ影響しない順にします。

間違い：ないキーをインデクサーで読む

C# · 失敗を学ぶ例（そのまま起動しない）
var stock = new Dictionary<string, int>();
Console.WriteLine(stock["PEN"]);

この読み取りは登録がないためKeyNotFoundExceptionになります。空のDictionaryだから0を返すわけではありません。ないことが通常の入力ならTryGetValueで分けます。

C# · 独立したコード例
var stock = new Dictionary<string, int>();
if (stock.TryGetValue("PEN", out int quantity))
    Console.WriteLine(quantity);
else
    Console.WriteLine("商品コードが未登録です");

期待出力は商品コードが未登録ですです。見つからない場合を0と扱うか、未登録として返すかは仕様次第です。「在庫0の商品」と「存在しない商品」は異なる状態なので、業務上必要なら区別を残します。

段階別の練習

基礎はListへAdd・Remove・インデクサー代入を順に行い、各時点のCountを追う課題です。標準は商品コードの件数集計を、大文字小文字を区別する仕様へ変更する課題です。Ordinalを使うとsaveとSAVEは別のキーで、save=2、SAVE=1となります。

応用は、Listの先頭要素の削除を繰り返す処理と、先頭から読み進める処理の違いを考える課題です。大量の先頭削除は要素移動を繰り返すため、先入れ先出しが目的ならQueueという専用コレクションも候補です。構文だけでなく、行いたい操作から部品を選ぶことが目標です。次のLesson 16では、コレクション操作などで起きる例外をどこで受け取り、資源をどう片付けるかを学びます。
