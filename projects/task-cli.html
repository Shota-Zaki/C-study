JSON保存付きタスク管理

追加・一覧・完了・削除を実装し、アプリを終了してもデータを残す。

ゴール

  • コマンドごとに役割を分ける
  • JSONで保存と復元を行う
  • 破損ファイルを勝手に上書きしない

実装手順

  1. TaskItemをrecordで定義し、メモリ上で追加・完了を動かす。
  2. list/add/done/deleteコマンドを作る。
  3. JSONの保存と読み込みを追加する。
  4. ファイル不存在と破損を分け、エラー時に既存データを保護する。

設計と実装の考え方

① ID・表示番号・データの寿命

TaskItemはGuid Id、string Title、bool Done、DateTimeOffset CreatedAtを持ちます。IDはタスクを識別する値であり、一覧の行番号ではありません。途中のタスクを削除しても、残ったタスクのIDを書き換えません。タイトルが同じ二件も、別のIDを持つ別タスクです。

作成時刻はUTCで保存し、必要に応じて表示時にローカルへ変換します。recordのwithで完了状態を変えるときは元のIDと作成時刻を維持します。完了はtoggleではなくDone=trueとするので、同じdoneコマンドを二回実行しても未完了へ戻りません。

② コマンドと検証の表を先に書く

listは追加引数なし、addはタイトル一つ、doneとdeleteはGUID一つを要求します。タイトルはTrim後1〜100コード単位、件数上限は1000です。タイトル内の空白を一引数として渡すため、シェルでは引用符で囲みます。利用者入力の失敗をIndexOutOfRangeExceptionで発見するのではなく、引数数を先に検査します。

whereは保存先を表示するだけ、helpは使い方だけを表示します。これらは保存データを読む必要がありません。不明コマンドも、ファイル操作より前に拒否します。副作用が不要な操作を先に分けることで、誤入力が保存へ到達しにくくなります。

③ 保存場所と読込の契約

保存先はLocalApplicationData/CSharpLearningLab/tasks.jsonです。dotnet runの作業場所に依存しない個人用データ領域を使い、whereで実際のパスを表示します。別のPCや別ユーザーでは別の領域です。教材フォルダーをコピーしただけでタスクデータも移るわけではありません。

Loadではファイルなし・フォルダーなしだけを初回として空Listへ変換します。それ以外のアクセス失敗やJSON破損はエラーとして止めます。json.Lengthで確認する上限は読んだ文字列の長さであり、ファイルを読む前のバイト上限ではありません。巨大入力を扱う本番設計なら、ストリームや読み込み前の制限を別に検討します。

④ 読めたJSONの中身も検証する

Deserialize<List<TaskItem>>が成功しても、null、空GUID、空白タイトル、100文字超、既定の作成時刻、重複IDなどを許してはいけません。サンプルはこれらをLoadの境界で検査し、使えるListだけをアプリへ返します。復元したListへnullの要素が混ざる可能性も条件に含めています。

型名がTaskItemだから正しいタスクだと考えないことが重要です。手編集や旧形式でデータが変わる可能性があります。将来スキーマを変更するときは、保存形式のバージョンと移行処理を設計し、わからない形式を既定値で埋めて無言で上書きしないようにします。

⑤ 保存の成功前と成功後を分ける

追加・完了・削除をメモリ内で行い、Saveが成功した後に成功メッセージを出します。保存できていないのに「追加しました」と表示すると、利用者はデータが残ったと誤認します。Saveは同じディレクトリに一時ファイルを書き、書き終えた後にFile.Moveで置き換えます。

この方式は直接上書きの途中破損を減らす狙いですが、停電時の耐久性、二つのプロセスから同時保存したときの競合、OSごとの全条件を保証しません。二プロセスが同じ初期Listを読み、順に別内容を保存すると、後勝ちで更新を失い得ます。単一プロセス限定という条件をREADMEにも残します。

⑥ データ破損の検証を安全に行う

既に使っているtasks.jsonへ直接不正文字を書かないでください。専用OSアカウント・使い捨て環境か、保存先をテスト用ディレクトリへ差し替えられるリファクタリングで隔離します。テスト前後でファイル内容を比較し、読込失敗によって空JSONへ置き換わっていないことを確認します。

正常な再起動確認も重要です。一回目のプロセスでadd→終了→二回目のプロセスでlistとして、メモリ内だけに残っているのではないことを確かめます。削除テストは今回作成したIDに限定し、別の練習データを勝手に消さないようにします。

初回のファイル不存在と、JSON破損やアクセス拒否は同じ状態ではありません。

ファイルがない初回だけ空の一覧として開始します。他の読み込み失敗は通知して元ファイルを保持し、不正な空データで上書きしないようにします。

サンプル実装

csharp
using System.Text.Json;

string root = Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
    "CSharpLearningLab");
string path = Path.Combine(root, "tasks.json");
string command = args.FirstOrDefault()?.ToLowerInvariant() ?? "help";
if (command == "where") { Console.WriteLine(path); return 0; }
if (command == "help")
{
    Console.WriteLine("コマンド: list / add \"タイトル\" / done ID / delete ID / where");
    return 0;
}
if (command is not ("list" or "add" or "done" or "delete"))
{
    Console.Error.WriteLine("不明なコマンドです。引数なしで使い方を表示します。");
    return 1;
}
try
{
    List<TaskItem> tasks = Load(path);
    switch (command)
    {
        case "list":
            if (args.Length != 1) throw new ArgumentException("listに追加の引数は不要です。");
            foreach (var item in tasks.OrderBy(x => x.CreatedAt))
                Console.WriteLine($"[{(item.Done ? "x" : " ")}] {item.Id} {item.Title}");
            Console.WriteLine($"{tasks.Count}件 / 完了{tasks.Count(x => x.Done)}件");
            return 0;
        case "add":
            if (args.Length != 2 || string.IsNullOrWhiteSpace(args[1]) || args[1].Trim().Length > 100)
                throw new ArgumentException("タイトルは1〜100文字。空白を含む場合は引用符で囲んでください。");
            if (tasks.Count >= 1000) throw new ArgumentException("タスクは1000件までです。");
            var added = new TaskItem(Guid.NewGuid(), args[1].Trim(), false, DateTimeOffset.UtcNow);
            tasks.Add(added);
            Save(path, tasks);
            Console.WriteLine($"追加: {added.Id} {added.Title}");
            return 0;
        default:
            if (args.Length != 2 || !Guid.TryParse(args[1], out Guid id))
                throw new ArgumentException("listに表示された有効なIDを指定してください。");
            int index = tasks.FindIndex(x => x.Id == id);
            if (index < 0) throw new ArgumentException("対象のタスクがありません。");
            if (command == "done") tasks[index] = tasks[index] with { Done = true };
            else tasks.RemoveAt(index);
            Save(path, tasks);
            Console.WriteLine(command == "done" ? "完了にしました。" : "削除しました。");
            return 0;
    }
}
catch (Exception ex) when (ex is IOException or UnauthorizedAccessException or JsonException or ArgumentException)
{
    Console.Error.WriteLine($"処理を中断しました: {ex.Message}");
    Console.Error.WriteLine($"保存先: {path}");
    return 1;
}

static List<TaskItem> Load(string path)
{
    string json;
    try { json = File.ReadAllText(path); }
    catch (FileNotFoundException) { return new List<TaskItem>(); }
    catch (DirectoryNotFoundException) { return new List<TaskItem>(); }
    if (json.Length > 2_000_000) throw new JsonException("保存データが大きすぎます。");
    var tasks = JsonSerializer.Deserialize<List<TaskItem>>(json)
        ?? throw new JsonException("保存データがnullです。初期化せず中断します。");
    if (tasks.Count > 1000 || tasks.Any(x => x is null || x.Id == Guid.Empty ||
        string.IsNullOrWhiteSpace(x.Title) || x.Title.Length > 100 || x.CreatedAt == default) ||
        tasks.Select(x => x.Id).Distinct().Count() != tasks.Count)
        throw new JsonException("保存データの内容に不正があります。初期化せず中断します。");
    return tasks;
}
static void Save(string path, List<TaskItem> tasks)
{
    Directory.CreateDirectory(Path.GetDirectoryName(path)!);
    string temporary = path + "." + Guid.NewGuid().ToString("N") + ".tmp";
    try
    {
        File.WriteAllText(temporary, JsonSerializer.Serialize(tasks,
            new JsonSerializerOptions { WriteIndented = true }));
        // 同一ディレクトリの一時ファイルから置き換える。複数プロセスの排他制御ではない。
        File.Move(temporary, path, overwrite: true);
    }
    finally
    {
        if (File.Exists(temporary)) File.Delete(temporary);
    }
}
public record TaskItem(Guid Id, string Title, bool Done, DateTimeOffset CreatedAt);

同じIDへdoneを二回実行する場合の契約です。完了を反転する操作ではありません。

一覧の行番号ではなくGUIDで対象を指定します。保存後に別の実行でlistしても完了状態が残ることまで確認します。

完成条件

  • add "C#を30分学習"の後、別の実行でlistすると同じタスクが残る。
  • done IDで完了状態になり、delete IDで削除できる。
  • 壊れたJSONを読み込むとエラーで終了し、元ファイルを上書きしない。
  • whereで実際の保存パスを表示できる。
制約・対象外

単一ユーザー・単一プロセス向けです。同時起動した複数プロセスの競合制御や、停電時の完全な永続性は保証しません。重要データは別途バックアップしてください。
