Project 01

支出集計CLI

引数の検証、decimal、record、LINQでカテゴリ別の支出を集計する。

このページの目次
ゴール実装手順設計と実装の考え方サンプル実装完成条件テスト観点

ゴール

  • 引数をカテゴリ:金額として解析する
  • カテゴリ別合計と総額を表示する
  • 不正な金額を理由付きで拒否する

実装手順

  1. まず固定配列からカテゴリ別合計を出す。
  2. コマンドライン引数から支出を読み取る。
  3. 空欄・負数・不正形式の検証を加える。
  4. 正常系と境界条件を確認する。

設計と実装の考え方

① 仕様を数値と境界で固定する

一引数を「カテゴリ:金額」とし、最後のコロンで分割します。カテゴリはTrim後1〜40 UTF-16コード単位、金額は0超〜1,000,000,000、小数は数値として小数2桁へ丸めても変わらない値を受け入れます。引数は最大1000件、通貨は一種類という学習上の規則です。空白や桁区切りを金額に許すかはパース設定で変わるので、今回はAllowDecimalPointだけを使います。

「小数2桁以内」は入力文字列の桁数ではなく値で検査しています。そのため1.230のように末尾0が多い値も1.23と同じなら通ります。文字列として必ず最大2桁という要件なら、別の書式検証が必要です。またカテゴリ内のコロンは最後の分割位置より前なら保持されます。サンプルの実際の契約を読まず、思い込みの期待値を作らないでください。

② データ型を決める

ExpenseはCategoryとAmountを持つrecordです。一件の支出を関連する二つの値として扱い、List<Expense>へ検証済みの入力だけを追加します。金額にはdecimalを使い、表示ではInvariantCultureの0.##で不要な末尾0を省きます。decimalを使っただけで会計上の規則が自動的に決まるわけではありません。

最大1000件、一件10億という制限なら総額の上限は10^12で、decimalの範囲より十分小さく収まります。こうした入力上限から集計結果の上限を見積もる習慣を付けます。この教材は税額計算・通貨換算・負数の返金処理を行わないため、それらを勝手に追加しないでください。

③ パースの処理順を追う

LastIndexOfで区切り位置を得る→左端や右端なら拒否→左をTrimしてカテゴリにする→右をdecimal.TryParseで変換→範囲と小数条件を確認→Expenseへ変換、の順です。チェックの前にListへ追加すると不正データが集計へ混入するため、追加は最後に行います。

文字列スライスarg[..separator]は開始からコロン直前まで、arg[(separator+1)..]はコロンの後ろから末尾までです。開始位置は含み終了位置は含まないという境界を、具体的な文字列と添字で確認してください。形式・型変換・業務ルールのどこで失敗したかを分けられるようになったら、次の改善としてTryParseExpenseへ取り出せます。

④ 集計と表示を切り離す

GroupBy(x=>x.Category)は同じカテゴリのExpenseをまとめます。group.Keyが名前、group.Sum(x=>x.Amount)がカテゴリ合計です。全体のSumはカテゴリごとのループの外で一回だけ表示します。OrderBy(...,StringComparer.Ordinal)で環境の文化に頼らない順序を指定します。

カテゴリの大小文字や表記ゆれを自動的にまとめる仕様はありません。「Food」と「food」を同じものにするなら、GroupByの比較規則、保存表記、出力順をまとめて設計し直します。単にToLowerするだけでは見せたい名前が失われることがあります。まずはOrdinalの明確な契約を守って完成させます。

⑤ 終了コードと標準出力を観察する

正常結果はConsole.WriteLine、入力エラーはConsole.Error.WriteLineへ出します。トップレベルのreturn 0は正常、return 1は失敗の終了コードです。PowerShellでは直後の$LASTEXITCODEで確認できます。ログに「エラー」と表示されても終了コード0なら、他のツールからは成功と判断されることがあります。

不正な引数が途中にあった場合、カテゴリ別結果はまだ出していないので、途中までの集計を誤って成功結果として使われにくくなります。全引数を検証してから集計する設計の利点です。この順序を、最初の一件ずつ結果を出すストリーム処理へ変えるなら、部分成功の契約が必要になります。

⑥ 実装例を読む前の分割課題

まず固定のExpense三件から1300、200、1500を得る関数を作ります。次に一引数だけをパースする関数を作り、空欄と負数を試します。それぞれが独立して動いてから、argsをループする入口を接続します。最後に標準エラーと終了コードを確認してください。

完成後の改善は一度に一つ行います。TryParseExpenseの抽出→カテゴリ別集計の純粋関数化→xUnitでパーサーと集計を個別検証、という順なら振る舞いを変えずに設計を改善できます。実装例の一文字単位の模写ではなく、なぜ検証後に追加するのかを説明できることを到達点にします。

サンプル実装

csharp
using System.Globalization;

if (args.Length == 0)
{
    Console.WriteLine("使い方: dotnet run -- 食費:500 食費:800 交通費:200");
    return 0;
}
if (args.Length > 1000)
{
    Console.Error.WriteLine("1回に指定できる支出は1000件までです。");
    return 1;
}
var expenses = new List<Expense>();
foreach (string arg in args)
{
    int separator = arg.LastIndexOf(':');
    if (separator <= 0 || separator == arg.Length - 1)
    {
        Console.Error.WriteLine($"形式が不正です: {arg}（カテゴリ:金額で指定）");
        return 1;
    }
    string category = arg[..separator].Trim();
    string amountText = arg[(separator + 1)..];
    if (category.Length is < 1 or > 40 ||
        !decimal.TryParse(amountText, NumberStyles.AllowDecimalPoint,
            CultureInfo.InvariantCulture, out decimal amount) ||
        amount <= 0m || amount > 1_000_000_000m ||
        decimal.Round(amount, 2) != amount)
    {
        Console.Error.WriteLine($"入力が不正です: {arg}（カテゴリ1〜40文字、金額0超〜10億、小数2桁以内）");
        return 1;
    }
    expenses.Add(new Expense(category, amount));
}
foreach (var group in expenses.GroupBy(x => x.Category).OrderBy(g => g.Key, StringComparer.Ordinal))
    Console.WriteLine($"{group.Key}: {Format(group.Sum(x => x.Amount))}円");
Console.WriteLine($"合計: {Format(expenses.Sum(x => x.Amount))}円");
return 0;

static string Format(decimal value) => value.ToString("0.##", CultureInfo.InvariantCulture);
public record Expense(string Category, decimal Amount);
Terminal
dotnet run --project samples/projects/expense-cli -- 食費:500 食費:800 交通費:200

完成条件

  • 食費:500 食費:800 交通費:200で、食費1300、交通費200、合計1500になる。
  • 金額abc、負数、空のカテゴリを拒否する。
  • 引数なしでは使い方を表示し、ファイルやネットワークに書き込まない。
制約・対象外

保存機能はありません。コマンド実行時に渡された支出だけを集計します。通貨換算や会計上の端数処理は対象外です。
