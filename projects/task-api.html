タスク管理Web API

CRUD・入力検証・DI・HTTPステータスを、ローカルAPIとして組み合わせる。

このページの目次
ゴール実装手順設計と実装の考え方サンプル実装完成条件テスト観点

ゴール

  • HTTPからタスクを作成・取得・完了・削除する
  • 共有ストアの操作を同期する
  • 正常系と400・404を確認する

実装手順

  1. GET /healthとGET /tasksを作る。
  2. POST /tasksでタイトルを検証し、201とLocationを返す。
  3. PUTによる完了とDELETEによる削除を追加する。
  4. 別ターミナルからPowerShellでHTTP契約を確認する。

設計と実装の考え方

① エンドポイントと状態遷移を設計する

GET /healthは稼働確認、GET /tasksは一覧、GET /tasks/{id:int}は個別取得、POST /tasksは作成、PUT /tasks/{id:int}/completeは完了、DELETE /tasks/{id:int}は削除です。先にこの表と期待ステータスを確定させ、ルートごとに必要な入力と出力を書きます。

TaskItemはId、Title、Doneを持ちます。完了操作は反転ではなくtrueへの設定なので同じPUTを繰り返しても状態は変わりません。DELETEの二回目が404になることは、削除対象が存在しないという今回の応答契約です。HTTP上の冪等性はレスポンスの数字が毎回同じという意味ではなく、効果に注目します。

② 要求DTOと保存データを分ける

CreateTaskRequestはTitleだけを受け取り、IdとDoneはサーバー側で決めます。利用者が任意のIDや完了状態を作成要求で直接上書きする設計にしないことで、書き込み可能な項目を限定します。タイトルは空白不可、Trim後100文字以内という契約です。

IDは今回のプロセス内の連番で、最大値と件数上限を確認します。再起動後も世界で一意な識別子ではありません。外部へ公開するシステムへ移すなら、保存先、採番、認証済み利用者の所有権を設計し、連番かGUIDかだけでセキュリティが完成すると考えないでください。

③ ハンドラーとTaskStoreの責務

ハンドラーは入力の解釈・検証を行い、TaskStoreの結果を200・201・204・400・404・409へ変換します。TaskStoreはDictionaryと採番の状態を管理し、HTTPのResultsを返しません。そのため、ストアの振る舞いをHTTPから独立してテストできます。

TaskStore.Addがnullを返すのは件数上限または採番上限という、この実装の限定された契約です。将来失敗理由が増えたら結果型へ分けてください。ストアが検証済みタイトルだけを受け取る前提も明示し、別の呼び出し入口が増えた場合はどこで同じ不変条件を守るかを見直します。

④ Singletonとlockの範囲を読む

TaskStoreはSingletonなので複数要求から同時に使われます。Dictionaryの読み書き、採番、件数チェックと追加を同じgateのlockで保護します。特に「1000件未満か確認→IDを増やす→追加」は一つの論理操作であり、別々の保護では間に他の要求が入る可能性があります。

Allはlockの中で配列へコピーして返し、外側がDictionaryの列挙中に更新される問題を避けます。TaskItemは不変な位置指定recordとして扱うため、この用途ではコピーした配列から変更可能な共有Listを露出しません。lock内でHTTP通信や長時間I/O、awaitをしない設計です。複数プロセス間の排他にはこのlockは届きません。

⑤ HTTPで作成から削除まで一本通す

新規起動→空一覧200→POSTで201→LocationへGET200→PUTでDone=true→同じPUTを再送してtrue維持→DELETE204→GET404、という順を一本のシナリオにします。IDを1と決め打ちせず、作成応答から取得したIDを後続へ渡すと再実行しやすくなります。

不正タイトルのPOSTは400になるだけでなく一覧件数を変えないことを確認します。ルートのabcは:intへ一致せず404、POSTへtext/plainを送った場合は期待するJSON Content-Typeの契約に合わず415になることを確認します。フレームワークが先に拒否した場合と自作検証で拒否した場合は、本文形式が異なる可能性も記録します。

⑥ テストを層ごとに分ける

単体ではTaskStoreの追加・取得・完了・削除・上限を検証します。統合では実際のHTTPへ要求を送り、ルーティング、JSONバインド、ステータス、ヘッダーを確認します。WebApplicationFactoryへ移すときはWebプロジェクト参照と対応するテストパッケージを追加し、テストごとにストアの状態を初期化します。

この配布物にはPython標準ライブラリでローカル起動中APIへ要求する検証スクリプトも含めます。スクリプトは学習用のタスクを作成して操作するため、使い捨ての本サンプルAPIにだけ向けてください。サイトのJavaScriptが動いたことは、このC# APIが起動したことの代わりにはなりません。

⑦ 公開前に残る設計を列挙する

再起動でデータが消えるのでDBと移行・バックアップが必要です。利用者ごとの認証と対象タスクの所有権確認、HTTPS、要求サイズやレートの制限、秘密情報の管理、ログと監視も未実装です。TaskStoreへlockがあるからインターネット公開して安全という判断はできません。

次に進むなら、一度に全部ではなく「ストアをSQLite等へ差し替えてAPI契約を維持する」「認証と所有権の拒否ケースを追加する」など一つの縦の変更へ絞ります。まず今回のローカルCRUDをテスト表どおりに再現し、何ができて何ができていないか説明して完了にします。

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<TaskStore>();
builder.Services.AddProblemDetails();
var app = builder.Build();
app.UseExceptionHandler();
app.MapGet("/health", () => Results.Ok(new { status = "ok" }));
app.MapGet("/tasks", (TaskStore store) => Results.Ok(store.All()));
app.MapGet("/tasks/{id:int}", GetTask);
app.MapPost("/tasks", CreateTask);
app.MapPut("/tasks/{id:int}/complete", CompleteTask);
app.MapDelete("/tasks/{id:int}", DeleteTask);
app.Run("http://127.0.0.1:5080");

static IResult GetTask(int id, TaskStore store)
{
    var task = store.Find(id);
    return task is null ? Results.NotFound() : Results.Ok(task);
}
static IResult CreateTask(CreateTaskRequest input, TaskStore store)
{
    if (string.IsNullOrWhiteSpace(input.Title) || input.Title.Trim().Length > 100)
        return Results.BadRequest(new { error = "タイトルは1〜100文字です。" });
    var task = store.Add(input.Title.Trim());
    return task is null
        ? Results.Conflict(new { error = "登録できるタスク数の上限に達しました。" })
        : Results.Created($"/tasks/{task.Id}", task);
}
static IResult CompleteTask(int id, TaskStore store)
{
    var task = store.Complete(id);
    return task is null ? Results.NotFound() : Results.Ok(task);
}
static IResult DeleteTask(int id, TaskStore store)
    => store.Delete(id) ? Results.NoContent() : Results.NotFound();

public record CreateTaskRequest(string? Title);
public record TaskItem(int Id, string Title, bool Done);
public sealed class TaskStore
{
    private readonly object gate = new();
    private readonly Dictionary<int, TaskItem> tasks = new();
    private int nextId;
    public TaskItem[] All()
    {
        lock (gate) return tasks.Values.OrderBy(x => x.Id).ToArray();
    }
    public TaskItem? Find(int id)
    {
        lock (gate) return tasks.GetValueOrDefault(id);
    }
    public TaskItem? Add(string title)
    {
        lock (gate)
        {
            if (tasks.Count >= 1000 || nextId == int.MaxValue) return null;
            var task = new TaskItem(++nextId, title, false);
            tasks.Add(task.Id, task);
            return task;
        }
    }
    public TaskItem? Complete(int id)
    {
        lock (gate)
        {
            if (!tasks.TryGetValue(id, out var task)) return null;
            return tasks[id] = task with { Done = true };
        }
    }
    public bool Delete(int id)
    {
        lock (gate) return tasks.Remove(id);
    }
}

完成条件

  • POST /tasksで201、Locationに新しいタスクのURLが入る。
  • 空白タイトルは400、存在しないIDは404になる。
  • 完了操作の再実行でも完了状態を維持する。
  • 削除成功は204、削除後の取得は404になる。
  • 再起動でデータが消えることを説明できる。
制約・対象外

メモリ保存の学習用APIです。再起動でデータは消えます。認証・権限管理・永続DB・インターネット公開は対象外です。127.0.0.1だけで待ち受けます。
