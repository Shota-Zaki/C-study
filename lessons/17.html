Lesson 17 · Chapter 5

ラムダ・デリゲート・イベント

処理を値として受け渡す。

.NET 10 / C# 14
本文・演習詳細解説
重要ラムダ式は処理を表します。デリゲート変数を呼び出したときに、その処理が実行されます。

数値だけでなく「数値をどう変えるか」という処理も渡せます。名前のあるメソッドとの対応を確認してラムダ式を読み、外側の変数やイベントの通知へ進みます。

要点

  • FuncとActionを使い分ける
  • ラムダの引数と戻り値を読める
重要

デリゲートは処理を値として扱う型で、Func/Actionやラムダ式と組み合わせます。キャプチャされる変数の値がいつ評価されるかも追います。

C#
x => x * 2

処理を値として受け渡す

ラムダ式は「短いメソッド」だけでなく、処理そのものを引数や変数として扱う入口です。何を受け取り何を返す処理なのかを型から読み、変数のキャプチャとイベントの購読期間まで確認します。LINQを暗記せず読めるための土台になります。

デリゲートは呼び出せる値

デリゲートは「この引数を受け取り、この型を返す処理」を型として表します。Func<int, int>はintを1つ受け取りintを返します。Funcの最後の型引数が戻り値です。戻り値がない処理はActionやAction<string>を使います。メソッドの結果を渡すのではなく、呼び出せる処理を渡す点が重要です。

デリゲート型は処理の入出力を表す

Func<int,bool>はintを一つ受け取りboolを返す処理の型です。最後の型引数が戻り値を表します。Func<int,int,int>なら二つのintを受け取りintを返します。Action<string>はstringを受け取り、戻り値を持たない処理です。変数へラムダ式や互換性のあるメソッドを代入し、変数名に括弧を付けて呼び出します。

C#のデリゲートは「呼び出せる処理」を型として表します。FuncやActionはよく使う形をあらかじめ用意したデリゲート型です。型を読むときは「入力→出力」を日本語で言い直し、式の短さより呼び出し側の期待する契約を確認します。

Func<int, int>は、整数を一つ受け取り、整数を一つ返す処理の型です。数値を保存するintとは役割が違います。

最後の型引数が戻り値の型です。Action<string>は文字列を受け取りますが、呼び出し結果の値は返しません。

ラムダは小さな関数の書き方

x => x * 2の左は引数、右は結果です。複数行なら(x, y) => { return x + y; }と書けます。=>はラムダ式の入力と処理を区切ります。外側の変数を参照するラムダは、その変数を取り込みます。作成時の値が常に固定されるわけではないため、外側の値を後で変えると結果が変わり得ます。

式形式とブロック形式、純粋な処理

x => x * 2は一つの式の結果を返します。x => { int doubled=x*2; return doubled; }は文のブロックを持ちます。返り値のあるブロックでは必要な経路にreturnが必要です。ラムダの引数型は代入先などの文脈から推論されるため、短いコードでも型がなくなるわけではありません。

LINQの条件や変換に渡す処理では、要素から結果を計算するだけの形が読みやすくなります。ラムダの中で外側のListへ追加したりカウンターを増やしたりすると、呼び出し回数や列挙タイミングで状態が変わります。副作用が必要な操作と、値の変換を意識して分けます。

名前のあるメソッドとラムダ式

処理そのものを受け渡す理由

メソッドの引数へ数値や文字列を渡すことは既に学びました。今度は「どの計算をするか」も渡します。デリゲートは、引数と戻り値の形が一致するメソッドを呼び出すための型です。ボタンが押された後の処理、データを残す条件、並べ替えの比較など、共通の手順に差し替え可能な処理を組み込むために使います。

ラムダ式はその場で小さな関数を記述する構文です。イベントは、出来事が発生したことを通知し、登録された処理を呼ぶ仕組みです。この三つは同義語ではありません。「どんな処理を渡せるか」がデリゲート、「処理をどう書くか」がラムダ式、「誰が通知を発生させてよいか」を管理するのがイベントです。

最小例：名前のあるメソッドから始める

C# · 独立したコード例
Func<int, int> operation = Double;
int result = operation(4);
Console.WriteLine(result);

static int Double(int value)
{
    return value * 2;
}

期待出力は8です。Func<int, int>の最後の型引数は戻り値、それより前は引数です。この場合「intを一つ受け取り、intを返す処理」です。Doubleの後ろに()を付けずに代入している点が重要です。ここではDoubleを実行せず、後から呼べるものとして渡しています。operation(4)で初めて4を渡して呼び出します。

Double(4)の戻り値8をデリゲートへ代入することはできません。処理と処理結果は別の種類の値です。

続き：処理順・状態変化・修正例を読む →

FuncとActionを呼び出す

csharp
Func<int, int> doubleValue = x => x * 2;
Action<string> log = message => Console.WriteLine(message);
log($"結果: {doubleValue(4)}");

int factor = 2;
Func<int, int> multiply = x => x * factor;
factor = 3;
Console.WriteLine(multiply(4));

multiplyの作成後にfactorを2から3へ変更しています。呼び出し時にどの値を使うか、実行順に追います。

この例は外側の変数factorを使います。ラムダ作成時の2を保存したつもりでも、multiply(4)の実行時には3を読み、12を返します。

想定出力

結果: 8 12

処理順

  1. doubleValueには計算結果ではなく処理が格納される。
  2. 呼び出すと4×2が計算され、logに表示用の文字列を渡す。
  3. multiplyが取り込んだfactorは呼び出し時には3になっている。

外側の変数を使うラムダ式

キャプチャするのは変数であって当時の値とは限らない

ラムダから外側のローカル変数を参照すると、その変数を後でも使えるようにキャプチャします。threshold=10でラムダを作った後threshold=20へ変更すれば、呼び出し時に20を読む例になります。登録時の値を固定したいなら別のローカル変数へスナップショットを作り、その変数を変更しないようにします。

forの制御変数をそのまま複数のラムダへキャプチャすると、すべてが同じ変数を見るため、ループ終了後には同じ値になることがあります。各反復のブロック内でcopy=iを作ると、それぞれのcopyを保持できます。staticラムダは外側のローカル状態をキャプチャしないことを明示でき、不要な依存を防ぐ選択肢です。

しきい値を後から変更すると何が起きるか

csharp
int threshold = 10;
Func<int, bool> currentRule = value => value >= threshold;
int snapshot = threshold;
Func<int, bool> fixedRule = value => value >= snapshot;
Console.WriteLine(currentRule(15));
threshold = 20;
Console.WriteLine(currentRule(15));
Console.WriteLine(fixedRule(15));

True False True

実コード例

実例：割引ルールを差し替える

同じ価格に、100円引きと10%引きの異なる計算を適用します。

C# · Program.cs
Func<int, int> coupon = amount => Math.Max(0, amount - 100);
Func<int, int> tenPercent = amount => amount * 90 / 100;
int price = 1500;
Console.WriteLine(coupon(price));
Console.WriteLine(tenPercent(price));

このコードの図解：処理を値として受け渡す

想定出力

1400
1350

処理と値の変化

  1. Func<int, int>入力と戻り値の型がintの契約
  2. coupon100円引き。ただし負数にならないよう0を下限にする
  3. tenPercent価格の90%を整数計算する
条件を変えた場合

priceが100未満のときcouponは0になります。金額の丸めが必要な業務ではdecimalと丸め規則を検討します。

よくある間違いと修正

よくある間違い

ラムダは短さのためだけに使うものではありません。複雑な分岐や副作用が増えたら名前のあるメソッドに分けると、読解とテストが楽になります。

forの後で全部3と表示される

修正箇所: for内で登録するラムダのキャプチャ

修正前

csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++) actions.Add(() => Console.WriteLine(i));
foreach (var action in actions) action();

修正後

csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    int copy = i;
    actions.Add(() => Console.WriteLine(copy));
}
foreach (var action in actions) action();
変更理由

各反復のブロック内にコピー用変数を作り、その反復での値を保持します。同じ制御変数iを全ハンドラーが共有する状態から、反復ごとの変数を参照する状態へ変える修正です。

修正後の確認

  • 0,1,2を順番に表示
  • ループ回数0なら表示なし
  • 登録後に呼ぶ場合でも各値が残る

通知の購読と解除

イベントは通知の窓口

eventは通知の購読を公開する仕組みです。外側は+=で購読し、-=で解除します。通常、イベントを発火できるのは宣言した型の内部です。長く生きるオブジェクトへ購読したままだと、購読側が参照され続ける場合があります。画面の破棄などに合わせて購読解除が必要か確認します。

イベントの購読・通知・解除を別々に考える

eventは外部が処理を登録・解除できる通知の仕組みです。発行するクラスはイベントを発火し、利用側は+=で購読、-=で解除します。イベントを外部から自由に上書き・発火できる普通の公開デリゲートフィールドとは違い、発行側の境界を保ちます。?.Invokeは購読者がいない場合のnullを扱います。

発行側が長く生きると、登録したハンドラーを通して購読側が参照され続けることがあります。画面を閉じたときなど、購読期間の終わりに解除します。別々に書いた同じ見た目のラムダを-=へ渡しても、登録したデリゲートと同じとは限りません。解除する必要があるハンドラーはメソッドか変数で保持してください。

イベントは、呼び出し元が一人の処理を直接選ぶ代わりに、登録された購読先へ通知する仕組みです。

購読を解除する必要がある場合は、登録したものと対応するハンドラーを使います。発行側が長く生きると、解除しない購読先への参照も残り得ます。

確認問題

Q1. Func<int, string>が表す処理は？
正解：最後の型引数が戻り値です。

たとえばn=>$"{n}点"という処理を代入できます。intを入力し、計算結果としてstringを受け取る呼び出しの契約です。

解説：型引数の順序が逆です。

Funcの最後の型引数が戻り値なので、順序を逆に読んでいます。stringを受けてintを返すならFunc<string,int>です。

解説：戻り値なしにはActionを使います。

戻り値がない処理ならAction<int>などを使います。Func<int,string>にはstringという結果を返す契約があります。

解説：非同期かどうかはこの型だけでは決まりません。

このデリゲートの結果はstringであり、型名だけから別スレッドや非同期待機は発生しません。非同期の結果ならFunc<int,Task<string>>など別の契約になります。

Q2. 外側の変数factorを参照するラムダを作り、その後factorを変更すると？
解説：値のスナップショットを常に作るわけではありません。

外側の変数を捕捉する場合、常にその時点の値を独立コピーするわけではありません。factorの共有と、呼び出すタイミングを追います。

正解：キャプチャする変数の状態が結果に影響します。

factor=2でラムダを作ってから3へ変えれば、呼び出し時に3を使う場合があります。固定したいなら別の変数へ値を保存する設計をします。

解説：通常は有効なコードです。

通常のローカル変数を後で変更し、それをラムダから読むことは可能です。有効なコードだからこそ、共有の意味を理解する必要があります。

解説：constへ変換する機能はありません。

constは宣言時に指定する定数の仕組みです。ラムダから参照したという理由で元の変数が書き換え禁止になることはありません。

Q3. Func<int,string>の意味は？
解説：データの組ではなく呼び出せる処理の型です。

Funcは後から呼べる処理の型です。intとstringの二つの値をまとめるならタプルやrecordなど、別のデータ構造を使います。

解説：戻り値なしの一般的なデリゲートにはActionを使います。

その契約ならAction<int,string>が候補です。Funcの型引数を全て入力として読まず、最後の一つを戻り値として分けます。

正解：入力がint、出力がstringである処理を表します。

処理を呼ぶときにintを渡し、戻ったstringを受け取ります。例としてvalue=>value.ToString()がこの形に対応します。

解説：Funcの最後の型引数が戻り値です。

最初が入力、最後が出力です。単語の見た目ではなく型引数の位置を確認すると、ラムダ式が期待する形か判断できます。

Q4. 外側の変数を読むラムダを作った後、その変数を変更した場合は？
解説：変数を変更しただけでデリゲートが解除されることはありません。

デリゲート変数へ別の値を代入したりイベント購読を解除したりしていません。外側の値の変更は、登録した処理の消滅とは別です。

解説：C#では変更される変数のキャプチャも可能です。

変わる変数を後から使える仕組みがキャプチャです。安全な利用には、どの変数を共有しているかと寿命を把握します。

解説：固定値の自動コピーだと理解するとキャプチャを誤解します。

固定の写真ではなく同じ変数を使う場合があります。forのiを捕捉して後から呼ぶと最後の値を読む例が、この誤解を表します。

正解：同じ変数をキャプチャしていれば変更後の値を読みます。

呼ぶ時点で共有変数が何を持つかによって計算が変わります。生成時と呼び出し時を別々の行として追跡してください。

Q5. 後で解除するイベントのハンドラーはどう扱う？
解説：長寿命の発行元が購読者を参照し続ける可能性があります。

イベント発行元が生きている間、登録した処理を通して購読者も参照され続ける場合があります。不要になった購読の解除を所有側で管理します。

解説：別のラムダは登録したものと同じデリゲートとは限りません。

同じ見た目のラムダでも別のデリゲートになり得ます。解除する対象を確実に特定するため、登録時の値や同じメソッドと対象を使います。

正解：購読したハンドラーを特定して解除します。

Action<int> handler=...と保持して+=し、不要時に同じhandlerを-=します。誰が登録し、どの時点で解除するかも設計します。

解説：eventは外部から自由に代入するためのフィールドではありません。

eventは外部が通知一覧を自由に上書きするためのフィールドではありません。購読側に許す操作を登録・解除へ絞るための宣言です。
