概念と内部の仕組み

null対策は「!を付けて警告を消すこと」ではありません。値がない可能性を型に表し、値がないときの仕様を決め、必要な境界で実際に検証することです。null許容参照型とnull許容値型は似た表記でも仕組みが違うため、分けて整理します。

ないかもしれない値を表現する

string?はnullを許す参照型の注釈です。Nullableが有効なプロジェクトでは、コンパイラーがnullの可能性を追跡し、危険な参照に警告します。ただし実行時に自動でnullを拒否する仕組みではありません。stringとstring?は、実行時には同じ参照型です。

int?は別の仕組み

intは値型なので、そのままではnullを代入できません。int?はNullable<int>として「値あり／なし」を表現します。参照型のstring?と同じ記号を使いますが、型としての仕組みが異なります。Valueを読む前にHasValueを確認するか、??などを使って代替値を設計します。

?.と??をつなぐ

name?.LengthはnameがnullならLengthを呼ばず、結果もnullにします。そのため結果の型はint?です。name?.Length ?? 0とすれば、nullのときだけ0を選びます。!は「nullではないと扱って」とコンパイラーに伝えるだけで、実行時チェックも値の変換も行いません。外部入力ではifで検証し、正当な根拠なしに!を付けないことが重要です。

string?は実行時の別クラスではない

Nullableが有効なプロジェクトでは、stringはnullを想定しない参照、string?はnullを許容する参照として静的解析されます。注釈と処理の流れから、危険なアクセスに警告が出ます。しかしstringとstring?は実行時に別々のCLR型になるわけではなく、非null注釈が外部入力を自動的に検証するものでもありません。

たとえばnull注釈のない古いライブラリ、JSON、リフレクションなどの境界では、期待に反してnullが流入する可能性を考えます。コンパイラーの警告と実行時の入力検証は役割が違います。DTOにstringを使ったからAPIが必ず適切なエラーを返すと決めつけず、フレームワークのバインドと検証設定も確認します。

フロー解析が安全性を追えるコードにする

if (name is null) return;と先に異常系を終了させると、その後のname.Lengthは非nullとして読めます。これをガード節と呼びます。深いifの中へ正常処理を入れ続けるより、正常な値だけが残った状態を作る方が読みやすい場面があります。nullでよい値なら、早期終了ではなく代替表示や欠損として保持する方針も選べます。

後置の!はnull免除演算子で、コンパイラーへ警告を抑えるよう伝えます。値を変換したり、nullなら例外を早めに投げたりする実行時処理は追加されません。name!.Lengthはnameが実際にnullなら例外になります。安全性の根拠をコードで示せるなら、!よりガードや型の見直しを優先します。

?.と??は欠損を伝え、代替値を決める

name?.LengthはnameがnullならLengthへアクセスせずnullを返します。Length自体はintですが、結果が存在しない場合があるため式の型はint?になります。name?.Length ?? 0とすれば、左がnullのときだけ0を使ってintへまとめられます。空文字はnullではないのでLength=0になりますが、欠損と空が同じ表示になるのはこの設計で意図した結果です。

??の右辺は左辺がnullのときだけ評価されます。CreateDefault()のようにコストがある処理を右へ置く場合もこの順序を理解します。?.を連ねるとどこかがnullの場合に結果が欠損になりますが、途中のどのデータが欠けたかを区別したいなら明示的な分岐が適しています。単に短くするために業務上の失敗理由まで消さないようにします。

int?・null・空欄・未入力のモデル

int?はNullable<int>という値型で、値があるかどうかとintの値を組み合わせて持ちます。HasValueがfalseのときValueへアクセスすると例外になるため、パターンや??で処理する方が安全です。0点と未受験を同じ0で表すと情報が失われるので、未受験をnullにするというモデルには意味があります。

文字列でもnull、""、" "は異なる値です。表示名のようにいずれも未入力扱いにしたければstring.IsNullOrWhiteSpaceを使います。一方、外部システムで空文字に意味がある場合は勝手にnullへ統一しません。nullを消すこと自体ではなく、欠損の意味を業務ルールへ正しく対応させることが目標です。

概念をもう一段掘り下げる

nullは空文字や0ではなく「参照する値がない」

参照型の変数はオブジェクトをたどるための参照を保持します。オブジェクトとは実行中に存在する型の実体です。stringの文字列も参照型です。nullはその参照がどの実体も指していないことを表します。""は長さ0の文字列という実体があり、"null"は四文字の普通の文字列です。

nullを無視すると、存在しない相手に対してLengthを読んだりメソッドを呼んだりして、NullReferenceExceptionが起こります。これはコンパイル後の実行時に起こる例外です。一方、nullable reference typesは、nullの可能性をソース上の型へ注釈し、危険な使い方をコンパイラーが警告する機能です。実行時に新しい別の参照型を作る機能ではありません。

.csprojで<Nullable>enable</Nullable>を有効にして学習します。警告は実行を必ず止めるものではなく、設定によっては警告があってもビルドできます。null非許容と書けば外部データから絶対にnullが来ない、という実行時の保証にはなりません。

string?とint?は同じ仕組みではない

string?は参照型のnull許容注釈です。stringとstring?は実行時には同じ型で、コンパイラーが意図と経路を検査します。int?はNullable<int>という値型で、整数値と値が存在するかという情報を扱います。普通のintはnullを保持できません。

記述 何を表すか 主な扱い方
string nullでないことを意図する参照 null警告を減らして契約を明示
string? nullを含み得る参照 使用前に経路や代替値を決める
int 整数値 0も有効な整数
int? 値なし、または整数 HasValueやパターン、??を使う

0を「値がない」の代わりに使うと、無料価格0や点数0と区別できないことがあります。int?なら値なしと0を別の状態として保持できます。ただしnullを認めればよいのではなく、その状態が業務として何を意味するかも定義します。

よくある間違いと修正

よくある間違い

name!にしても、実際にnullならname!.Lengthは実行時に失敗します。警告を消すことと、不具合を修正することは別です。

!を付けてもNullReferenceExceptionになる

修正箇所: nullの可能性がある名前の長さ取得

修正前

csharp
string? name = null;
Console.WriteLine(name!.Length);

修正後

csharp
string? name = null;
if (name is null)
{
    Console.WriteLine("名前なし");
    return;
}
Console.WriteLine(name.Length);
変更理由

!は警告抑制でありnullを消しません。今回は欠損ならメッセージを出して終了する仕様にし、その後は値があることを分岐で保証します。長さ0で代替する仕様なら?.Length ?? 0も別解です。

修正後の確認

  • null→名前なし
  • 空文字→0
  • C#→2

// 課題とテストケースを読んで、自分で実装してください。

入力例・前提条件

既存の文字列保存済みと、nullの二つを順に評価する。

考え方のヒント

??の右辺は必要なときだけ評価されるので、DefaultNameの表示回数を予想する。

入力するとlocalStorageへ保存実行・自動採点は行いません
解答例と確認ポイント
csharp
string? existing = "保存済み";
string? missing = null;
Console.WriteLine(existing ?? DefaultName());
Console.WriteLine(missing ?? DefaultName());
static string DefaultName()
{
    Console.WriteLine("既定値を生成");
    return "ゲスト";
}

想定出力

保存済み 既定値を生成 ゲスト
  • 最初の??は左側で決まるためDefaultNameを呼ばない。
  • 二つ目はnullなので関数を呼び、関数内の表示が先に出る。
  • 関数が返したゲストを外側のWriteLineが表示する。評価順と表示順を結び付けて読む。
入力 / 条件期待結果
両方非null生成メッセージ0回
片方null生成メッセージ1回
両方null生成メッセージ2回

処理と結果の読み解き

保存済みでは左辺をそのまま使い、生成の表示は出ない。nullでは右辺を呼び、生成の表示と既定値を受け取る。評価時点を出力の順に対応付ける。

よくある別解と選び方

先にifでnullを判定する形も同じ意図を表せる。右辺を先に変数へ入れると不要でも呼ばれるので等価でない。

よくある間違いと確認箇所

??の両側を必ず実行すると考えない。副作用のある右辺を前へ移す書き換えで動作が変わる。

実務へのつながり：重い既定値生成や検索などで、必要なときだけ処理する意味を理解する。

確認問題

Q1. string? name = null; name!.Length はどうなる？
解説：!は代替値を作りません。

Lengthへアクセスする対象はnullのままです。0へ置き換えたいなら?.Length ?? 0のように条件付きアクセスと代替値を明示します。

解説：!は文字列変換をしません。

!はnullを""へ変換しません。空文字を用意したいなら?? ""などで別の値を選びますが、欠損の意味を残すか先に決めます。

正解：null参照を実際に参照するので例外になります。

コンパイラーの警告を抑えても実行時の値は変わりません。nullに対して実体のプロパティを読もうとするためNullReferenceExceptionになります。

解説：!はコンパイラーへの注釈で、実行時チェックではありません。

末尾の!はnull許容解析への注釈です。if(name is null)のような分岐が挿入されるわけではないので、安全性の根拠にはできません。

Q2. nameがstring?のとき、name?.Lengthの型は？
解説：Lengthは長さの整数です。

Lengthは文字列そのものではなく数を返すプロパティです。?.は対象がない可能性を加えますが、戻り値をstringに変換しません。

解説：nameがnullなら結果もnullになり得ます。

nameがnullならLengthを呼ばずnullを返すので、通常のintだけでは結果を表せません。nullを表せるint?が必要です。

解説：真偽値を返す演算ではありません。

?.は条件付きでメンバーへアクセスする演算です。nameがあるかをtrue/falseで返す式にしたいなら、name is not nullなどを使います。

正解：値型のLengthにnullの可能性が加わります。

通常のLengthはintですが、アクセスを省略した場合のnullも持つためint?になります。空文字なら0、nullならnullと区別できます。

Q3. name!.Lengthの!は何をしますか？
正解：開発者が非nullだと判断していることを静的解析へ伝えます。

自分の判断を解析に伝えるだけなので、その判断が間違っていれば実行時に失敗します。値が非nullになる経路を説明できる場合に限って検討します。

解説：try/catchとして使う処理は行われません。

例外を処理するにはtry/catchなど別の仕組みが必要です。!を書いてもNullReferenceExceptionを捕捉して続行する処理は増えません。

解説：実行時のチェックや分岐は追加されません。

実行時の分岐を追加するのはifや?.などです。警告の抑制と、実際に危険なアクセスを避けることを混同しないでください。

解説：値を書き換える演算子ではありません。

代替値の選択なら??を使います。!は元の変数へ代入しないため、後から読んでもnullのままの場合があります。

Q4. string? name=null;のときname?.Lengthの型と値は？
解説：条件によりboolを返す比較式ではありません。

比較式ではないのでboolのfalseにはなりません。nullかどうかを判断することと、条件付きで長さを取得することは別の操作です。

正解：Lengthはintですが、nullの場合も表せるようint?になります。

nameがnullなのでLengthへ進まずnullになります。結果の型はint?であり、後からHasValueやパターンなどで有無を判断できます。

解説：長さの取得は文字列を返す処理ではありません。

文字列の取得ではなくLengthという数値プロパティの取得です。nullを空文字にする意味は?.にはありません。

解説：?.だけでは0という代替値を設定しません。

0は実際に空文字のLengthを読む場合の結果です。nullの結果を0へまとめたいときだけ??0を追加し、意味が失われないか考えます。

Q5. 未受験をnull、0点を0で保存しているとき、表示前に全件??0へ変換すると？
解説：??はこの用途で有効な演算なので必ず例外にはなりません。

nullable数値に??0を適用するのは有効です。問題は例外ではなく、元々異なる状態を同じ数値で表すことによる情報の損失です。

解説：nullを0へ置き換える向きであり、逆変換ではありません。

??は左がnullのとき右の値を選びます。既に0である値をnullへ戻す逆向きの変換はしません。

解説：異なる二つの状態を同じ値へまとめるので情報が減ります。

未受験と受験して0点は別の意味です。両方0へ変えた後の値だけでは、元がどちらだったかを復元できません。

正解：代替値を使う前に、欠損を区別する必要があるか判断します。

表示や集計で欠損をどう扱うかを先に決めます。未受験は「未受験」と表示し、点数の0は「0点」とする分岐なら情報を保てます。

理解チェックと公式資料

  • string?とint?の仕組みの違いを説明できる
  • !を実行時チェックとして使わない
  • ?.と??の評価順を追える
  • 欠損と0や空文字を業務上区別できる
