概念と内部の仕組み

ループを読めることと、ループの正しさを説明できることは別です。この単元では添字の範囲、各周回で変わる状態、空配列の場合、途中終了を追い、C#の配列とコレクションの役割の違いへつなぎます。

配列の長さは固定

int[] scores = { 70, 85, 90 };のように配列を作れます。添字は0から始まり、最後はLength - 1です。Lengthと同じ添字にはアクセスできません。配列の要素数を増やしたい場合は新しい配列かList<T>を使います。新しい構文を急いで覚えるより、型と添字の動作を確かめます。

位置が不要ならforeach

foreach (int score in scores)は各要素を順番に取り出します。foreachでは要素を受け取る変数の前に型を書き、inの後ろに列挙対象を書きます。要素番号が必要ならforが適しています。通常のforeachの反復変数へ直接代入して配列の要素を置き換えることはできません。書き換えが必要なら添字で対象を指定します。

まずforで集計を理解する

合計変数をループの外に置き、要素を1つずつ足します。平均は(double)sum / scores.Lengthで求めます。ただし空配列のときにどうするかも決めます。後からLINQを学んだとき、SumやAverageがどんな処理を隠しているのか理解しやすくなります。

配列の長さと有効な添字

new int[3]は3個のintを持つ配列を作り、各要素は0で初期化されます。有効な添字は0、1、2で、Lengthは3です。長さと最後の添字は同じではありません。forの条件はi < values.Lengthが基本で、i <= values.Lengthでは最後に範囲外へアクセスします。

配列は作成後に長さを変更できません。追加・削除が必要な場合はList<T>を検討します。Array.Resizeは配列オブジェクト自体を伸ばすというより、必要に応じて新しい配列へ置き換えるAPIです。また配列は参照型なので、int[] second = first;は各要素のコピーではありません。別々に変更したいなら複製が必要で、参照型の要素の深いコピーとはさらに別問題です。

forとforeachの判断基準

添字が必要、特定範囲だけ処理したい、配列の要素へ代入したい場合はforが分かりやすくなります。各要素を順に読むだけならforeachにすると、開始値・終了条件・加算処理を自分で管理する箇所が減ります。効率を測定せずに片方を常に速いと決めつけないでください。

通常のforeachの反復変数へ再代入しても、コレクションの要素を書き換える構文にはなりません。配列の数値を更新するならvalues[i] = ...と対象を明示します。一方、要素がクラスで、そのプロパティを変更する場合は参照先を更新できることがあります。変数そのものの再代入と参照先の更新は、Lesson 13でも詳しく扱います。

集計変数とループ不変条件

sum=0から始めて各要素を加えると、k件処理した時点のsumは「先頭k件の合計」です。この途中状態の意味がループ全体を通して成立するように考えると、初期値や更新式の誤りを発見しやすくなります。件数を数えるならcountは「これまで条件に一致した件数」を表します。

合計と件数を毎周回で0へ初期化すると、前の要素の結果が失われます。初期化の位置をループの外にする理由を、変数のスコープだけでなく状態の意味から説明してください。空配列では本体が一度も実行されず、sumやcountが初期値のままになることも仕様として確認します。最大値を求める処理なら、初期値0が正しいとは限りません。

continue・break・returnと変更中の列挙

continueは今の周回の残りを飛ばして次へ、breakは最も内側のループを抜け、returnは現在のメソッドを終えます。無効なデータを読み飛ばす、最初に見つかったら検索を終える、処理自体を終える、の三つを区別します。ネストしたループではbreakが全ループを抜けるわけではありません。

List<T>をforeachで列挙しながらAddやRemoveすると、列挙が無効になり例外になることがあります。削除対象を別に集める、RemoveAllを使う、添字と削除方向を設計する、といった方法を選びます。whileでは終了へ近づく更新が抜けると無限ループになるため、条件だけでなく状態がどう変わるかも確認します。

概念をもう一段掘り下げる

配列は「同じ型の複数の値を、位置で扱うもの」

配列は要素を順序付きでまとめる型です。要素とは配列に入っている一つの値です。毎日の学習時間をday1、day2、day3という別の変数へ入れると、日数が増えるたびに変数と計算を追加する必要があります。配列なら一つの名前から各要素へアクセスし、同じ処理を繰り返せます。

インデックスは要素の位置を示す整数です。C#の通常の一元配列では先頭が0、最後がLength - 1です。Lengthは要素数なので、要素数そのものの位置は存在しません。3要素なら位置は0・1・2です。この「個数」と「最後の位置」の違いが範囲外アクセスを防ぐ基礎です。

配列の長さは生成後に変更できません。要素の値は代入で変更できます。配列変数へ別の配列を代入することもできますが、それは元の配列の長さを伸ばしたわけではありません。追加や削除を繰り返す場合に使うList<T>はLesson 15で扱います。

文法・実例・処理順

csharp
int[] scores = { 70, 85, 90 };
int sum = 0;
foreach (int score in scores)
{
    sum += score;
}
Console.WriteLine($"人数: {scores.Length}");
Console.WriteLine($"合計: {sum}");

想定出力

人数: 3 合計: 245

処理順

  1. sumは0から始まる。
  2. 70を足して70、85を足して155、90を足して245になる。
  3. Lengthは要素数3。配列の添字の最大値は2である。

値・状態の変化を追う

読み飛ばしを含む合計と件数

csharp
int[] values = { 10, -5, 20, 0 };
int sum = 0;
int count = 0;
foreach (int value in values)
{
    if (value < 0) continue;
    sum += value;
    count++;
    Console.WriteLine($"value={value}, sum={sum}, count={count}");
}
Console.WriteLine($"最終: {sum}/{count}");

出力

value=10, sum=10, count=1 value=20, sum=30, count=2 value=0, sum=30, count=3 最終: 30/3
段階値・状態読み解き
開始前sum=0、count=0まだ有効な要素を一件も読んでいない
10sum=10、count=1有効値なので合計と件数を更新
-5sum=10、count=1のままcontinueで更新と出力を飛ばす
20sum=30、count=2前の結果へ加算
0sum=30、count=3合計は変わらないが有効件数には含まれる

よくある間違いと修正

よくある間違い

forの条件をi <= scores.Lengthにすると最後に範囲外へ進みます。i < scores.Lengthにし、0件・1件のデータでも確認してください。

最後の一周だけ添字が範囲外になる

修正箇所: for文の終了条件

修正前

csharp
int[] items = { 2, 4, 6 };
for (int i = 0; i <= items.Length; i++)
    Console.WriteLine(items[i]);

修正後

csharp
int[] items = { 2, 4, 6 };
for (int i = 0; i < items.Length; i++)
    Console.WriteLine(items[i]);
変更理由

配列の長さが3なら最後の添字は2です。i=3の周回へ進まないよう、<=を<へ変更します。空配列も自然に0周になることを確認してください。

修正後の確認

  • 3要素が2,4,6の順に表示される
  • 空配列で何も表示せず終わる
  • 1要素でその値だけ表示する

  • 空配列やすべて負数の場合は平均を定義できないので先に終了する。
  • 合計をdoubleへ変換してから割ることで、小数を含む平均にも対応する。
入力 / 条件期待結果
10,-1,20,030 / 3 / 10.0
1,23 / 2 / 1.5
-1,-2対象なし

処理と結果の読み解き

有効値は10、20、0で合計30、件数3、平均10。負数を飛ばしたときは件数も増やさない。平均の表示をF1などで10.0へ整える。

よくある別解と選び方

対象の一覧を先に作ってから集計する方法は後のLINQで扱う。ここでは一回のループの中で二つの状態を更新する。

よくある間違いと確認箇所

0を無効値と誤認すると件数2、平均15になる。全て負数の入力では0で割らず対象なしを表示する。

実務へのつながり：欠損・対象外・0という実値の違いを守ることが、正しい統計や集計に必要になる。

確認問題

Q1. 要素数3の配列で、最後の有効な添字は？
解説：3は要素数であり、有効な添字ではありません。

最初の添字が0なので、3要素は0、1、2へ対応します。Lengthと同じ3を使うと存在しない4番目を読もうとします。

解説：要素数3の配列の添字は0〜2なので、4は範囲外です。

添字4は0から数えて5番目の位置です。配列の要素数を超えた場所へ進んでも自動で配列が伸びることはありません。

正解：0、1、2の3つです。

最後はLength-1で2です。ただし空配列には有効な添字がないので、常に最後の要素を読めるという意味ではありません。

解説：LengthそのものではなくLength - 1です。

Lengthは件数です。上限として比較するならi<Lengthにし、添字として直接Lengthを使わないようにします。

Q2. 要素番号が不要な読み取り走査に適した構文は？
解説：配列には要素追加のAddメソッドはありません。

配列の長さは作成後に変えません。要素の走査ならforeach、追加が必要ならListなど目的に合う型を選びます。

解説：通常の走査には不要です。

gotoは処理位置を移す構文ですが、通常の順次走査はforeachで意図を明確に表せます。特殊な制御を増やす必要はありません。

解説：境界が誤っています。

i=Lengthも本体へ入るため範囲外へアクセスします。forを選ぶなら初期値0、条件i<values.Length、更新i++を確認します。

正解：要素を順番に扱う意図が直接伝わります。

添字の管理を手書きせず、各要素を順に受け取れます。要素番号や隣の要素へのアクセスが必要な場合はforも候補です。

Q3. Lengthが5の配列を全件読むforの条件は？
解説：i=5は6個目に相当し、範囲外です。

iは0、1、2、3、4、5まで進むので6回になります。最後の5はLengthと等しく、有効な添字の上限4を超えます。

解説：初回からfalseなので本体へ入りません。

初期値0では0>0がfalseです。forは最初に条件を確認するため、更新式まで進む前に一度も本体へ入りません。

正解：有効な添字0〜4をちょうど一度ずつ処理できます。

0から4の5回を処理し、iが5になると条件falseで終了します。処理回数と有効添字を対応させて確認できます。

解説：最後の添字4を処理しないため一件不足します。

0、1、2、3の4回で終わります。例外が出ないから正しいとは限らず、最後の要素を処理したかも確認します。

Q4. foreachの途中でcontinueを実行すると？
解説：メソッド全体を終えるのはreturnです。

returnは今のメソッドから戻ります。continueはループの現在の周回を打ち切るだけなので、作用する範囲が違います。

正解：continueは現在の周回だけを打ち切ります。

その要素の残りの文を実行せず、次の要素の取得へ進みます。元のコレクションの内容はこの命令だけでは変更しません。

解説：ループを抜けるbreakとも終了範囲が異なります。

breakは最も内側の対象ループなどを抜けます。continueは次の周回へ進むため、外側の全ループを終了するものでもありません。

解説：制御フローの変更であり、要素の削除ではありません。

要素を消すにはList.Removeなどの明示的な操作が必要です。制御の飛び先とデータの状態変化を同じものと考えないでください。

Q5. 最大値の初期値を常に0にすると困るデータは？
解説：正数があれば通常はその値で更新されます。

正数があれば0より大きい値で更新されるため、この誤った初期値でも偶然正しく見えます。正常に見える一例では一般性を保証できません。

解説：そのデータでは0初期値の欠陥が現れない場合があります。

最大の正数へ更新されるので、0が含まれることだけでは欠陥が出ません。空や全負数など、初期値が結果へ残る条件も試します。

正解：全要素が0未満だと更新されず、存在しない0が結果になります。

{-5,-2,-8}なら本当の最大は-2ですが、0より大きい要素がないため0が残ります。最初の要素で初期化し、空の場合を別に処理する方法があります。

解説：その正数へ更新されるため、この欠陥を検出しにくい入力です。

{3}なら3>0で更新されるため通ります。一要素の負数{-3}なら同じコードが0を返すので、符号の条件も大切です。
