概念と内部の仕組み

値型と参照型は「スタックかヒープか」の丸暗記では理解できません。まず代入時に何がコピーされ、その後の変更がどこへ伝わるかを確認します。値型の中に参照型を含む場合まで追うことで、浅いコピー、引数、読み取り専用の意味がつながります。

値型は値をコピーする

int、bool、decimal、enum、structなどは値型です。変数を代入すると値がコピーされ、その後一方を変更しても、もう一方の値そのものは変わりません。struct内に参照型のフィールドがあれば、そのフィールドでは参照の値がコピーされます。値型だから全ての子オブジェクトが別になるわけではありません。

参照型は参照の値をコピーする

classの代入では同じオブジェクトを指す参照がコピーされます。一方からプロパティを変更すると、もう一方からも変わった値が見えます。これは変数そのものを参照渡ししたこととは違います。変数に別インスタンスを代入すると、片方だけ参照先が変わります。

スタック対ヒープだけで覚えない

「値型は必ずスタック、参照型は必ずヒープ」とだけ覚えると、classの中の値型フィールドやボックス化を説明できません。初心者の段階ではコピーと同一性の意味を先に理解します。小さな値を表す型にはreadonly structを検討できますが、性能目的でclassを一律にstructへ変えないでください。

分類の中心は格納場所ではなくコピーの意味

値型の変数には値型の値そのもの、参照型の変数には実体を指す参照値が入ります。通常の代入では変数の値をコピーします。structなら各フィールドを含む値がコピーされ、classなら参照値をコピーするので同じ実体を指します。intやdecimal、DateTimeなども値型です。

「値型は常にスタック、参照型は常にヒープ」と覚えると、クラスのフィールドに入った値型やボックス化を説明できません。実際の配置は使用場所やランタイムの最適化にも関係します。最初に保証される意味として、代入と引数渡しの後で何が独立し、何が共有されるかを追うことを優先してください。

浅いコピーは子オブジェクトを複製しない

structにint NumberとList<string> Tagsがあると、structのコピーはNumberの値とTagsの参照値をそれぞれコピーします。コピー後にNumberを変えると元のNumberは変わりません。しかしTags.Addで要素を追加すると、同じListを参照している元のstructからも追加が見えます。structだから内部のすべてが独立するわけではありません。

配列のToArrayやListのToListも、参照型要素を深く複製する操作ではありません。新しいコンテナーを作っても要素は同じ実体を指す場合があります。独立した編集履歴やスナップショットが必要なら、どの階層まで複製するのかを設計します。不変データの利用は共有による意図しない変更を減らす選択肢です。

classのメンバー更新と参照の差し替え

Counterを通常の引数で渡してValue=9にすると、共有しているCounterの状態が変わります。一方で引数へnew Counter()を代入しても、変わるのはそのメソッドのローカルな参照だけです。呼び出し元の変数を別オブジェクトへ差し替えるなら、戻り値を受けて代入するかrefなどの明示的な方法が必要です。

C#ではstructとclassで変数が保持する値の性質が異なるため、同じ形のメソッドでも対象型によってコピーされる値の中身が変わります。型だけでなく引数修飾子も確認し、refの有無を読み飛ばさないようにします。

ボックス化とstructの選び方

intなどの値型をobject型として扱う場合、値を包むオブジェクトが作られるボックス化が発生することがあります。箱へコピーした後に元のintを変更しても、箱の値は変わりません。アンボックス化は対応する元の値型として取り出す必要があり、objectに入ったintを直接longとして取り出すことはできません。

小さく、値そのものとして扱い、不変にしたいデータではreadonly structやreadonly record structが候補です。大きな可変structはコピーのコストと変更の見落としが増えるため慎重に扱います。classより速そうという推測だけでstructに変えず、意味の適合と必要な計測から判断します。

概念をもう一段掘り下げる

値型と参照型は「代入で何がコピーされるか」から学ぶ

値型は変数に値を保持し、通常の代入ではその値がコピーされます。参照型では変数が実体への参照を保持し、通常の代入では参照がコピーされます。参照とは、オブジェクトをたどるための値です。参照をコピーしても、それが指すオブジェクト全体を自動複製するわけではありません。

この区別を「値型はStack、参照型はHeap」とだけ覚えると、クラスのフィールド内のintや配列の要素を説明できなくなります。物理的な配置ではなく、値の意味、コピーされる範囲、実体の共有を先に理解します。Stackは呼び出し状態などに使う後入れ先出しの構造、Heapはオブジェクトなどを管理する領域です。配置には所有する型やJIT最適化も関係します。

最小例：intのコピー

C# · 独立したコード例
int a = 10;
int b = a;
b = 20;
Console.WriteLine($"a={a}, b={b}");

期待出力はa=10, b=20です。bはaに追従する名前ではなく、aからコピーした10を最初に保持する別の変数です。bへの代入はaを変えません。

時点 a b 説明
aの初期化後 10 未宣言 aへ10を保存
b=aの後 10 10 整数値10をコピー
b=20の後 10 20 bだけ更新

よくある間違いと修正

よくある間違い

可変structをコレクションやプロパティ経由で扱うと、コピーを変更したつもりになることがあります。用途が明確になるまでは小さく不変な値を表す使い方を優先します。

Listを代入しただけで独立コピーだと思う

修正箇所: 編集用リストを作る代入

修正前

csharp
var original = new List<int> { 1, 2 };
var editing = original;
editing.Add(3);
Console.WriteLine(original.Count);

修正後

csharp
var original = new List<int> { 1, 2 };
var editing = new List<int>(original);
editing.Add(3);
Console.WriteLine(original.Count);
Console.WriteLine(editing.Count);
変更理由

新しいListを作って要素をコピーします。今回は要素がintなので値も独立します。要素が変更可能なclassなら、Listの複製だけでは各要素の実体は共有されるため、必要なコピーの深さを別に決めます。

修正後の確認

  • 元の件数2、編集側3
  • 編集側の数値を書き換えても元の数値は変わらない
  • class要素へ変えた場合に深いコピーと誤解しない

  • ボックス化時に10がコピーされるので、その後のnumberへの代入とは別である。
  • boxedに格納された型はintなのでintとして取り出す。
  • longが必要なら一度intとして取り出した後に数値変換する。

処理と結果の読み解き

ボックス化時点で10を持つ値が包まれる。numberを20へ変えてもboxed内の10は変わらず、取り出したintは10。

よくある別解と選び方

intのまま別変数へコピーしても値の独立は見られる。objectへ包む型変換が加わる点を区別する。

よくある間違いと確認箇所

boxedを直接longとしてアンボックスしない。元の値型がintなら一度intへ取り出し、その後必要な数値変換を行う。

実務へのつながり：ジェネリックで要素型を保つ利点や、objectを使う場合の型・コピーを理解する。

確認問題

Q1. classの変数bへaを代入すると、通常コピーされるのは？
正解：同じオブジェクトを指す参照の値がコピーされます。

二つの変数は同じ実体をたどる値を持ちます。b.Valueを変えるとaからも同じ変更が見える場合があるのは、その実体を共有しているためです。

解説：深いコピーではありません。

子のListや配列まで独立した実体が新規作成されるわけではありません。深いコピーが必要なら、どこまで複製するかを明示して実装します。

解説：実行時の代入は型定義をコピーしません。

型定義はプロパティやメソッドの規則です。aからbへの代入はその規則を複製するのではなく、実行中の参照値を渡します。

解説：参照の値がコピーされます。

コピーがないのではなく、コピーする対象が参照値です。変数を二つ作っても実体が一つという図で確認すると理解しやすくなります。

Q2. structにList<int>フィールドがあり、そのstructをコピーした場合は？
解説：structのコピーは深いコピーではありません。

外側のstructをコピーしてもListの内部配列まで複製しません。Listのフィールドには参照値が入っているので、その値がコピーされます。

正解：フィールドの参照値がコピーされ、同じListを指します。

コピー前後のstructは別の値でも、両方のフィールドが同じListを指します。片方からAddすると、もう片方からも増えた内容が見えます。

解説：そのような変換はありません。

元に有効なList参照があれば、その参照値をコピーします。値型のコピーが参照型フィールドを自動初期化し直す仕組みではありません。

解説：参照型のフィールドを持つstructは定義できます。

structには参照型フィールドも持たせられます。値型であることは、内部の全ての値も値型でなければならないという制約ではありません。

Q3. structの中のListをコピー先からAddしたとき、元からも見える理由は？
解説：値と参照のコピー規則に沿った動作です。

通常のコピー規則で説明できるので、まずどの変数がどの実体を指すかを確認します。予想と違うだけで言語処理系の不具合と判断しません。

解説：無関係なListには影響せず、同じ実体だけが変わります。

Addは呼び出したList実体だけを変更します。元と先から同じ変更が見えるのは、無関係なListへ通知しているからではなく同じ実体だからです。

正解：外側の値をコピーしても内部の参照先までは複製しません。

外側のstructの値にはListへの参照も含まれます。その参照のコピーと、参照先のListをnewして複製することを区別します。

解説：型の種類が実行途中で変わるわけではありません。

structの型分類は変わりません。参照型のフィールドを含む値型、という元からの構造で共有を説明できます。

Q4. object boxed=10;からlongへ変換する適切な一例は？
解説：varは初期化式の型を推論するだけで任意の変換をしません。

var x=boxedなら初期化式の型はobjectです。中の値を望む数値型へ変換する処理を、varが代わりに行うことはありません。

解説：格納された値はintなので直接longへのアンボックス化はできません。

boxedにはintとしてボックス化した値が入っています。longとして直接アンボックス化すると、保存された値型と一致せずInvalidCastExceptionになります。

正解：まずintとして取り出し、それからlongへ数値変換します。

最初に(int)で元の値型として取り出し、次に(long)で数値を広い型へ変換します。アンボックス化と数値変換は別の段階です。

解説：objectにはこの名前の変換メソッドはありません。

objectにLongValueという標準メソッドはありません。存在しない便利メソッドを推測せず、元の型と変換の規則を確認します。

Q5. 値型と参照型を説明する基本として正確なのは？
解説：値型の実際の配置は使用場所などにも依存します。

クラスの中のintフィールドなど、値型も所有する実体の中に配置されます。Stack/Heapだけの暗記ではなく、コピー時の意味から理解します。

解説：クラスの通常の代入は参照値のコピーです。

classの通常代入は同じ実体への参照を増やす操作です。子の状態が独立することを期待するなら、別の生成・コピー処理が必要です。

正解：コピーの意味を基準にすると変更の伝わり方を説明できます。

値型の値をコピーする場合と、実体を指す参照値をコピーする場合を分けると、どの更新が共有されるかを説明できます。物理配置は次の理解段階です。

解説：参照型フィールドは参照値のコピーとなり、深い複製ではありません。

struct内の参照値も通常の値としてコピーします。入れ子のオブジェクトを再帰的にnewする意味は含まれないため、コピーの深さに注意します。

理解チェックと公式資料

  • 値型をスタックの暗記だけで説明しない
  • struct内の参照の共有を追える
  • ボックス化のコピーを説明できる
  • 参照先の更新と引数への再代入を区別できる
