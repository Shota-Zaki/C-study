C#と.NET、最初の実行

ソースから画面表示まで。

.NET 10 / C# 14
本文・演習詳細解説
重要C#のソースを書くこと、ビルドすること、実行することは別の作業です。

図解：ソースから画面表示まで

要点

  • C#と.NETの役割を説明する
  • SDKを確認してコンソールアプリを作る
重要

C#ソースは.NET SDKでビルドし、生成物を.NETの実行基盤で動かします。dotnet new / build / runの役割を分けて確認します。

C#
Console.WriteLine("学習開始");

概念・構文

この単元の目的はHello Worldを暗記することではありません。「ソースを書いた」「ビルドできた」「実行できた」を区別し、エラーが起きた段階に合った調査ができるようにします。C#で使うコマンド、SDK、Runtime、生成物の役割を最初に整理します。

C#は言語、.NETはその土台

C#はコードの構文と意味を定めるプログラミング言語です。.NETはC#コンパイラー、実行環境、標準ライブラリ、CLIなどを含む開発基盤です。SDKは開発用の道具一式、Runtimeは主に実行に必要な部分です。コードを書くPCには.NET 10 SDKを導入します。C# 14は.NET 10で利用できます。

Windowsで準備する

公式の.NETダウンロードページから.NET 10 SDKのWindows x64版を導入します。ARM版WindowsならArm64版を選びます。VS CodeにはC# Dev Kitを導入します。インストール後はターミナルを開き直し、dotnet --list-sdksで10.xのSDKを確認してください。Macでは本体のCPUに合うSDKを選びます。

最初のプロジェクト

任意の作業フォルダーで「dotnet new console -n FirstCSharp -f net10.0」「cd FirstCSharp」「dotnet run」の順に実行します。Program.csを下の例に置き換えて保存し、もう一度dotnet runを実行します。.csprojがプロジェクト設定、Program.csが実行するコードです。binとobjはビルド時に生成されます。

言語・SDK・ランタイム・ライブラリを分けて考える

C#は変数宣言やif文などの書き方と意味を定める言語です。.NET SDKはC#コンパイラー、プロジェクト作成、ビルドなどの開発用ツールを含みます。ランタイムは、作成したアプリケーションを実行するための基盤です。標準ライブラリはConsoleやListなど、アプリから呼び出す既存の型と処理を提供します。これらを全部「C#」と呼ぶと、何が不足しているか切り分けられません。

通常のC#プロジェクトではdotnet buildがプロジェクト設定を読み、ソースをコンパイルして成果物を生成します。dotnetは言語そのものではなくCLIの入口です。VS Codeは編集用のアプリであり、入れただけで.NET SDKが導入されたとは限りません。まずターミナルでSDKとビルドを確認し、その後にエディターの実行機能を使うと、設定トラブルを分離できます。

ソースから実行までの工程と生成物

通常の.NETプロジェクトでは、Program.csなどのソースがコンパイラーにより中間言語と型情報を含むアセンブリへ変換されます。一般的なJIT実行では、ランタイムが必要な処理を実行環境向けの機械語に変換します。Native AOTなど別の配布方式もありますが、最初は通常のビルドと実行を扱います。「C#は必ずこの方式だけ」と一般化しないことが大切です。

binには実行に使うビルド結果、objには中間生成物や復元情報が作られます。通常はこれらを手で修正しません。変更する正本は.csと.csprojです。dotnet runは必要なビルドも行うため、実行のたびにコンパイルエラーが表示されることがあります。出力が出る前に止まったなら、プログラムの途中ではなくビルド段階で止まっている可能性を確認します。

カレントディレクトリとプロジェクト指定

ターミナルには「現在いるフォルダー」があります。dotnet runを引数なしで実行すると、この場所のプロジェクトが探されます。エクスプローラーでProgram.csが見えていても、ターミナルが別の場所なら同じプロジェクトを指していません。Windows PowerShellのGet-LocationとGet-ChildItemで、場所と.csprojの存在を確認します。

毎回cdで移動する代わりに、dotnet run --project パスで対象を明示できます。教材ZIPでは各サンプルが独立したプロジェクトです。最上位フォルダーから実行する場合はsamples/lessons/lesson-01のように指定してください。パスに空白があれば引用符で囲みます。アプリへ渡す引数は--の後に置くと、dotnetコマンドの引数と区別できます。

三種類の失敗と調べる順番

「dotnetが見つからない」はコマンドやSDKの導入段階、「;が必要」「名前が存在しない」はコンパイル段階、「表示されたが値が違う」は処理の設計段階の問題です。すべてをSDKの再インストールで解決しようとすると、原因を隠し、余計な変更を増やします。エラーの最初の一件、ファイル名、行番号、エラー番号から読んでください。

まず標準の新規プロジェクトが動くことを確認し、次に表示文だけを変えます。この順なら、動かなくなった原因の候補は直近の小さな変更に絞れます。入力を増やす、クラスを増やす、ライブラリを追加する、といった変更を同時に行わないのは初心者限定の作法ではなく、実務の障害調査でも有効な進め方です。

仕組みの補足

プログラムの実行手順

プログラムとは、コンピューターに行わせる処理を順序と条件付きで記述したものです。「今月の学習時間を合計して表示する」なら、時間を用意し、足し算をし、結果を文字にして画面へ送る、という別々の仕事が必要です。人間なら補える「適当に合計して」の曖昧さをなくすために、C#の文法で一つずつ指定します。コードはその指示を書いた文章、ソースファイルはコードを保存したファイルです。

最初は、編集・保存・ビルド・実行・結果の確認を別の行動として理解します。画面に文字を書くだけではコンピューターに新しい指示は届きません。保存するとディスク上のファイルが変わり、ビルドするとそのファイルから実行用の成果物が作られ、実行すると成果物の指示に従って処理が進みます。期待と結果を照合して初めて、意図どおりのプログラムか判断できます。

「変数」は値を名前で参照するための仕組みです。int minutes = 20; は、整数を扱う型intの変数minutesを宣言し、20で初期化します。型とは、どの種類の値を扱い、どの操作を許すかという規則です。変数を使わず同じ20を何か所にも書くと、時間を変更するときに直し漏れが起きます。意味のある名前が、値の役割と変更場所を明らかにします。

メソッドとは、名前を付けた処理です。Console.WriteLine(...)は標準ライブラリが提供するメソッドの呼び出しで、かっこの中の値を画面へ書き、改行します。「標準ライブラリ」は.NETが用意する再利用可能な部品の集まりです。表示処理を自作せずに使えるため、自分が解きたい問題の処理に集中できます。メソッドを自分で定義する方法はLesson 07で扱います。

C#・SDK・CLR・IL・JITの分担

C#はコードを書くための規則です。.NET SDKはそのコードからアプリを作る道具一式で、プロジェクト作成用のひな形、コンパイラー、ビルドをまとめる道具などを含みます。コンパイラーは、C#として意味が通るかを検査し、別形式の命令へ変換するソフトウェアです。エディターは編集用の道具であり、SDKとは役割が異なります。

通常のプロジェクトをビルドすると、ILという中間的な命令と、型・メソッドなどの情報を持ったアセンブリが生成されます。アセンブリは配布や参照の単位で、多くの場合.dllファイルです。ILはC#の文章そのものでも、特定CPUの機械語そのものでもありません。型情報があるため、実行基盤は呼び出すメソッドや扱う値の種類を識別できます。

CLRは実行を支える基盤です。現行.NETの代表的な実装がCoreCLRです。一般的なJIT方式では、JITコンパイラーが必要に応じてメソッドをCPU向けの機械語に変換します。CLRはさらに、不要なオブジェクトのメモリを再利用可能にするGCや例外処理なども支えます。実際の変換回数やタイミングは最適化で変わるので、「全行を必ず一度だけ変換する」とは覚えません。

通常のコンソールアプリの実行過程を示した概念図です。Native AOTという、主な機械語変換を配布前に行う方式もあります。ソースの検査はコンパイル時、アプリの処理は実行時に行われます。

修正箇所: Program.csの出力文

変更理由

C#の識別子は大文字小文字を区別します。consoleとConsoleは別の名前です。メソッドを呼び出す文の末尾にはセミコロンが必要なので、名前と終端の二点を直します。実行時エラーではなく、ビルド時に検出される修正です。

修正後の確認

  • dotnet buildが成功する
  • 開始が1行出力される
  • 文字列だけを変更すると変更後の文が表示される
実コード例

実例：作業時間の集計

1日25分の作業を5日続けたときの合計を、分と時間で表示します。

C# · Program.cs
int minutesPerDay = 25;
int days = 5;
int totalMinutes = minutesPerDay * days;
int hours = totalMinutes / 60;
int minutes = totalMinutes % 60;
Console.WriteLine($"合計: {totalMinutes}分");
Console.WriteLine($"{hours}時間{minutes}分");

想定出力

合計: 125分
2時間5分

処理と値の変化

  1. 25 × 5totalMinutes に125を保存
  2. 125 / 60整数同士の除算なので hours は2
  3. 125 % 60割り切れずに残った5が minutes に入る
条件を変えた場合

daysを3にすると、合計75分、1時間15分になります。

確認問題

Q1. 自分でC#をビルドして実行するPCに必要なのは？
正解：SDKにはコンパイル・実行に必要な道具が含まれます。

C#のファイルから実行用の出力を作るにはコンパイラーとビルドの道具が必要です。SDKはその開発用の一式を含み、dotnet buildで確かめられます。

解説：Runtimeは実行側の部品であり、開発用SDKの代わりにはなりません。

既に作られたアプリを動かす役割と、ソースから作る役割を混同しています。Runtimeだけの端末に開発コマンド一式が揃うとは限りません。

解説：コードエディターだけではC#のコンパイルに必要な.NET SDKは導入されません。

エディターは文字を編集する道具です。入力補完が表示されても、対象SDKが導入済みかはdotnet --list-sdksで別に確認します。

解説：この教材はC#コンパイラーをブラウザに内蔵していません。

この静的サイトが提供するのは説明と下書きです。C#の実際のコンパイルは、別に準備したSDK環境で行います。

Q2. Program.csを書き換えた後、dotnet runで通常行われることは？
解説：ファイルを保存してから実行します。エディター内の未保存変更は反映されません。

ビルドが読むのは保存したファイルです。画面に変更が見えていても未保存なら、古い内容で起動して結果が変わらないことがあります。

正解：プロジェクトに対して実行すれば、必要なビルドの後に起動します。

対象の.csprojを基準に必要な復元・ビルドを行って起動するのが通常の流れです。明示的に--no-buildなどを付けた場合は条件が変わります。

解説：ローカル実行です。クラウド契約は不要です。

デプロイは作ったアプリを動かす環境へ配置する作業です。手元のdotnet runはそれを外部クラウドへ行う命令ではありません。

解説：通常のC#プロジェクトは.NET向けにビルドされ、.NETの実行基盤で動作します。

通常は.NET向けの出力を作り、その実行基盤で処理します。Webページを表示する教材と、サンプルC#アプリの実行方式を分けて考えます。

Q3. dotnet runでCSで始まるエラーとProgram.csの行番号が出て、表示処理が始まりません。最初に確認することは？
解説：まだ正常なアプリ実行に入っていないため、GC調査は順番が違います。

GCは実行中の不要オブジェクトを管理する仕組みです。ソースがコンパイルできない段階のセミコロン不足などとは調査対象が違います。

解説：ソースの構文エラーを通信速度で解決することはできません。

パッケージ取得の通信失敗と、CS番号が示すコンパイラー診断は別です。今回はProgram.csの行が示されているのでソースを先に確認します。

正解：コンパイルで止まっているので、該当行と直前の構文から確認します。

最初のエラーが後のエラーを引き起こすことがあります。示された行だけでなく、直前の括弧やセミコロンを確認して一つずつ直します。

解説：SDK自体が原因とは限らず、削除は原因切り分けになりません。

SDKの削除は環境を変えて別の問題を増やす可能性があります。まず再現するエラー内容と対象ファイルを残し、原因に合う修正を行います。

Q4. a=10、b=a*2を実行した後、a=30にしました。bは？
解説：通常の変数宣言と代入として有効な処理です。

int a=10; int b=a*2; a=30;という形は型の規則に合っています。エラーかどうかと、値が期待どおり変化するかは別の観点です。

解説：int変数が他の変数の変更でnullに変わることはありません。

intはこの宣言ではnullを保持しない値型です。aへの代入はbへの代入でも、bの型をint?へ変更する操作でもありません。

解説：bは式を保持するスプレッドシートのセルではありません。

bへ保存するのは代入時の計算結果です。式a*2を後から自動で再評価する仕組みは、この通常の変数宣言にはありません。

正解：代入時に計算した20を保持し、aへの後の代入では変わりません。

bを作った時点では10*2で20です。aを30へ変えた後、b=a*2をもう一度実行しない限りbは20を保持します。

Q5. 教材の最上位フォルダーからサンプル01を指定して実行するコマンドは？
解説：Consoleにサンプル番号を実行するこのようなAPIはありません。

Consoleは文字の入出力などを行う.NETの型です。サンプル番号は教材側の整理用の名前なので、その番号だけで起動するメソッドはありません。

正解：--projectで対象プロジェクトのフォルダーまたはファイルを指定できます。

今いるフォルダーからの相対パスで対象を選びます。別の場所から実行する場合はパスを合わせ、どのProgram.csをビルドするか確認します。

解説：usingはC#の名前空間参照などに使い、CLI実行の指定ではありません。

usingはC#ソースに書く指定で、ここで必要なのは端末のCLIコマンドです。ソースの文法とプロジェクトの起動操作を分けます。

解説：cdはフォルダーを移動するコマンドで、ソースファイルへ移動しません。

Program.csはファイルなので移動先フォルダーにはなりません。cdでプロジェクトのフォルダーへ移動してdotnet runする別の手順なら可能です。
