Lesson 23 · Chapter 6

asyncとawait

開始・待機・再開の順序。

.NET 10 / C# 14
本文・演習詳細解説
重要awaitは未完了のTaskを待つ間、呼び出し元へ制御を返せます。新しいスレッドを必ず作る命令ではありません。

読み込みが終わる前と後で、実行できる行が変わります。一つの非同期処理を使い、呼び出した直後に得るTaskと、await後に得る結果を分けて追います。

要点

  • TaskとTask<T>の役割を説明する
  • 非同期と並列処理を区別する
重要

Task/Task<T>は非同期処理の完了を表し、awaitは完了を待って継続します。非同期処理と並列実行を同一視しないでください。

C#
string result = await LoadMessageAsync();

開始した処理と完了後の結果

asyncは自動的に別スレッドを作る指定ではなく、awaitは単に処理を遅くする記号でもありません。Taskが表すもの、呼び出しの開始、未完了の待機、例外を受け取る位置を一つずつ追います。

Taskは将来の完了を表す

Taskは処理の完了、Task<T>は完了と結果Tを表します。asyncメソッドではawaitを使い、完了後に続きの処理を書けます。未完了の処理をawaitすると、そのメソッドは呼び出し元へ制御を戻せます。すでに完了している場合は続きへ進むため、awaitが必ず一時停止するとは限りません。

Taskは完了を表す。スレッドそのものではない

Taskは成功・失敗・キャンセルを含む処理の完了を表します。Task<int>なら成功したときにintの結果を得ます。メソッド名のAsyncは命名慣習であり、その文字だけで動作が変わるわけではありません。asyncを付けたメソッドでも、呼び出すと最初から別スレッドへ移動するわけではありません。

メソッドの本体は呼び出し時に始まり、未完了のawaitへ到達すると、続きの処理を後へ回して呼び出し側へ戻れるようになります。await対象がすでに完了していれば、その場で続行する場合があります。Taskを持つこととOSスレッドを一つ占有することを同じ図で説明しないでください。

非同期メソッドの呼び出し直後と、awaitした後では受け取るものが違います。

Taskは処理の完了・結果・失敗を表します。Taskの参照を変数へ保存しただけで、文字列の結果を取得したことにはなりません。

awaitは結果の取得と例外の受け取り位置

int score=await GetScoreAsync()は、完了後の結果をintとして受け取ります。待つ間に呼び出しスレッドを同期的にブロックするWaitやResultとは異なります。非同期メソッドが失敗すれば、awaitした場所で例外を受け取ってtry/catchで扱えます。

Taskを返したのに呼び出し側で待たず放置すると、完了や失敗を追えなくなる場合があります。特に保存や送信を始めてすぐアプリを終了すると、処理が最後まで終わる保証がありません。処理の所有者を決め、その所有者が完了と失敗を観測することが基本です。

Taskとして失敗が記録された非同期処理をawaitする場面です。

呼び出し側は、awaitを含む範囲をtry/catchで囲んで失敗を扱います。結果を使いたい処理では、Taskを受け取るだけで放置しないようにします。

一つの処理をawaitして結果を読む

csharp
Console.WriteLine("開始");
string result = await LoadMessageAsync();
Console.WriteLine(result);
Console.WriteLine("完了");

static async Task<string> LoadMessageAsync()
{
    await Task.Delay(30); // 待ち時間を学習用に再現する。
    return "読み込み結果";
}

LoadAsyncの結果がまだない場合を描いています。Task.Delayはここでは待ち時間を作るための例です。

awaitの後の行は、対象の処理が完了してから続きます。必ず新しいスレッドが作られる、または常に一度停止する、という意味ではありません。

想定出力

開始 読み込み結果 完了

処理順

  1. 開始を表示し、Task<string>を返す処理を呼ぶ。
  2. 未完了の待機をawaitし、完了後に文字列を受け取る。
  3. 結果、完了の順に表示する。処理順は読みやすく保てる。

明示的な合図でawait前後の順番を追う

csharp
var gate = new TaskCompletionSource<bool>(TaskCreationOptions.RunContinuationsAsynchronously);
Console.WriteLine("1: 呼び出し前");
Task<int> task = LoadAsync(gate.Task);
Console.WriteLine($"3: 完了済み={task.IsCompleted}");
gate.SetResult(true);
int value = await task;
Console.WriteLine($"5: 結果={value}");
static async Task<int> LoadAsync(Task signal)
{
    Console.WriteLine("2: await前");
    await signal;
    Console.WriteLine("4: await後");
    return 80;
}

出力

1: 呼び出し前 2: await前 3: 完了済み=False 4: await後 5: 結果=80
段階値・状態読み解き
呼び出しLoadAsyncの本体が始まるawait前の2を表示
未完了のsignalLoadAsyncは途中で呼び出し側へ戻るtaskは未完了
呼び出し側3を表示して合図を完了この例は待ち時間の長さに依存しない
続き4を表示して80を返すTask<int>が成功完了
await task80を取得して5を表示結果の利用は完了後

待ち時間と処理開始の関係

待ち時間と計算時間を区別する

ファイル、ネットワーク、データベースなどの処理では、CPUがずっと計算する時間だけでなく、外部の処理が完了するのを待つ時間があります。I/Oは入力・出力のことで、ファイルの読み書きや通信が代表例です。非同期処理は、こうした完了待ちを表現し、待っている間に呼び出し側へ制御を戻せるようにします。

Taskは、処理の完了・失敗・キャンセルなどを表すオブジェクトです。Task<T>は成功時にT型の結果も持ちます。Threadはコードを実行する流れです。Taskが一つあるから専用のThreadが一つ生まれる、という関係ではありません。非同期I/Oでは待っている間に専用スレッドを占有しない実装もあります。

用語 何を表すか 混同しないこと
同期 呼び出しの完了までその流れで待つ 常に悪いわけではない
非同期 完了を後から受け取れる 自動的に並列計算になるわけではない
並行 複数の処理が進行中である 同じ瞬間にCPUで実行とは限らない
並列 複数の処理を同時に実行 CPU資源や安全な共有が必要
Task 完了状態と結果を表す スレッドそのものではない
Thread 処理を実行する流れ Taskと一対一ではない

最小例：awaitで完了後へつなぐ

C# · 独立したコード例
Console.WriteLine("開始");
string result = await GetMessageAsync();
Console.WriteLine(result);
Console.WriteLine("終了");

static async Task<string> GetMessageAsync()
{
    await Task.Delay(10);
    return "受信完了";
}

期待出力は開始、受信完了、終了です。Task.Delayは指定した時間以上の待機を表すTaskを返します。正確に10ミリ秒で再開する保証ではありません。ここでは外部待ちを簡単に表す練習として使っています。

asyncは、そのメソッド内でawaitを使える非同期メソッドの形を指定します。awaitは対象が既に完了していれば結果をすぐに受け取り、未完了なら後続の処理を続きとして保存して、呼び出し側へ戻ります。Task<string>をawaitした結果の型はstringです。

実コード例

実例：データ取得の完了を待つ

Task.Delayで待ち時間を表現します。実際のネットワーク通信は行いません。

C# · Program.cs
Console.WriteLine("開始");
string result = await LoadAsync();
Console.WriteLine(result);
Console.WriteLine("終了");
static async Task<string> LoadAsync()
{
    await Task.Delay(20);
    return "取得完了";
}

取得完了
終了

処理と値の変化

  2. await結果が利用可能になるまで、後続の表示へ進まない
  3. 再開後取得完了、終了の順に表示する
条件を変えた場合

Task.Delayのミリ秒数は正確な実測時間を保証しません。待機の意味と結果の順番を確かめる例です。

サンプル一式 Program.cs

待機・スレッド・例外を混同しない

asyncは別スレッドを作る命令ではない

ファイルやHTTPのI/O待ちを非同期APIで待つと、待つためだけにスレッドを占有し続ける必要がありません。一方、重いCPU計算をasyncと付けるだけで速くすることはできません。CPU処理の別スレッド実行を検討するときはTask.Runなどが関係しますが、Webアプリで無条件に使う設計は避けます。

呼び出し側もawaitする

非同期処理の結果を.Resultや.Wait()で同期的に待つと、スレッドを塞ぎ、実行環境によってはデッドロックなどの問題につながります。非同期を呼び出し側までつなぎます。async voidは通常の業務メソッドではなく、主にイベントハンドラーなど戻り値制約のある場所で使います。

I/O待機とCPU計算を区別する

HTTPやファイルの非同期APIでは、外部の処理を待つ間にスレッドをブロックしないことが主な目的です。すでに非同期APIがある操作を毎回Task.Runで包む必要は通常ありません。awaitしても計算そのものが速くなるわけではありません。

重いCPU計算をUIスレッドから逃がす用途ではTask.Runが候補になりますが、サーバーの要求処理で何でもTask.Runへ投げれば処理能力が増えるわけではありません。まず何を待っているのか、どこでCPUを使うのかを特定します。非同期・並行・並列は関係しますが別の性質です。

async voidと呼び出し連鎖

結果のない非同期メソッドも、通常はTaskを返します。async voidは呼び出し側がTaskを受け取れず、完了の待機や例外の観測を通常の方法で行えません。イベントハンドラーなどvoidが要求される特別な境界を除き、業務処理ではTaskを選びます。

下位メソッドが非同期なら、それを呼ぶ上位もawaitしてTaskを返す形を連鎖させます。途中で.Resultや.Waitへ戻すと、応答性の低下や環境によってはデッドロックの原因になります。ConfigureAwait(false)は特定のライブラリ実装で検討するものですが、ブロックする設計を万能に修正する記号として付けないでください。

よくある間違いと修正

よくある間違い

Task.Delayは処理の待機を再現するための例です。ブラウザの見た目だけでC#の実行結果を作っているわけではありません。実コードは.NETで実行します。

呼び出し元が完了を待てないasync void

修正箇所: 業務メソッドの戻り値と呼び出し箇所

修正前

csharp

業務処理をTaskで返し、呼び出し側がawaitして完了を観測します。イベントハンドラーではないのでasync voidを使う理由がなく、待機と例外処理を呼び出し元へ戻せる形にします。

修正後の確認

  • 表示は待機後
  • 例外を投げればawait側へ伝わる
  • Taskを未観測で放置しない

確認問題

Q1. asyncをメソッドへ付けると必ず起きることは？
正解：非同期の状態管理を表します。別スレッドの生成とは別です。

メソッド内のawait前後の状態をコンパイラーが管理できる形にします。Threadをnewする指示ではなく、待ち方と続きの表現です。

解説：付けるだけでは並列になりません。

CPUの計算はasyncを付けただけでは別のCPUで同時実行されません。計算とI/O待ちを区別し、並列化が必要なら別に検討します。

解説：待ち方の改善であり、実行時間短縮の保証ではありません。

通信相手の応答時間そのものは変わりません。待機中にスレッドを占有しにくくする利点と、処理の絶対時間の短縮は別です。

解説：非同期処理も失敗します。

通信失敗や変換エラーは非同期でも起きます。返されたTaskをawaitし、必要な境界で例外やキャンセルを扱います。

Q2. 通常の非同期業務メソッドで結果intを返す戻り値型は？
解説：そのような戻り値型の書き方ではありません。

asyncはメソッドへの修飾子で、intの前に付ければ有効な非同期戻り値型になるわけではありません。結果を包むTask<int>などを使います。

正解：結果を持つ非同期処理として表せます。

呼び出し直後はTask<int>を受け取り、awaitで完了後のintを得ます。結果値に加えて失敗やキャンセルも同じ完了の仕組みで追えます。

解説：呼び出し側が完了や失敗を追いにくくなります。

async voidでは呼び出し側が完了をawaitできません。通常の業務メソッドでは、結果がなくてもTaskを返す方が追跡しやすくなります。

解説：標準の戻り値型ではありません。

Taskは完了を表し、Threadは実行する流れです。Thread<int>という形で結果付き非同期メソッドの戻り値を表す標準型はありません。

Q3. asyncを付けたメソッドは呼び出すと必ず新しいスレッドへ移る？
解説：Taskは完了状態と結果などを表す型です。

Taskは状態と結果を保持するオブジェクトです。実行に使われるスレッドの番号をそのまま返す値ではなく、一対一の対応もありません。

解説：asyncは新しいスレッド作成の指示ではありません。

最初の未完了awaitまでは通常の呼び出しとして同期的に進めます。asyncを見ただけで直後から別スレッドと決めつけないでください。

解説：本体は呼び出し時に実行を始めます。

呼び出しで本体が進み、既に完了したTaskへのawaitなら中断せず続くこともあります。awaitするまで何も始まらないという意味ではありません。

正解：呼び出し開始からawaitまでの処理を区別します。

未完了の処理にawaitしたところで続きの状態を保存して戻れます。開始時点、待機時点、再開時点を分けて観察します。

Q4. 通常の非同期保存処理で戻り値が不要な場合は？
正解：結果値がなくても完了と失敗を管理できます。

保存の結果値が不要でも、成功完了したか失敗したかは重要です。await後にだけ「保存できた」と表示する順序を作れます。

解説：スレッドをブロックする別の動作になります。

Thread.Sleepは呼び出し中のスレッドを止めます。Taskで非同期完了を表す設計の代わりにすると、待機の性質が変わります。

解説：型の契約が分かりにくくなります。

objectへ隠すと、呼び出し側が何を待つべきか型から読めません。Taskという明確な契約で完了を公開します。

解説：イベント等を除き完了を待てない設計になります。

async voidは主にvoidが必要なイベントハンドラーなどで使います。通常の保存処理までこの形にすると、完了と例外を上へつなぎにくくなります。

Q5. HTTPの非同期APIを呼ぶ基本は？
解説：すでに非同期なI/Oに追加スレッドを使う必要は通常ありません。

既に非同期のI/O APIは待機を表すTaskを返します。Task.Runで包むだけでは通信自体が速くなるわけではなく、不要な処理の移動になる場合があります。

解説：同期ブロックの問題を持ち込みます。

.Resultは同期的にスレッドを止めて待ちます。応答停止、スレッド不足、環境によってはデッドロックの原因になるため通常はawaitをつなぎます。

正解：ブロックせず完了と結果を扱う基本形です。

awaitで完了後の応答を受け、ステータスや本文を確認します。Tokenがあるなら対応引数へ伝え、失敗も呼び出し側で扱える形にします。

解説：awaitは回線速度や外部サーバーの処理を高速化しません。

awaitが変えるのは完了の待ち方です。回線帯域や相手の処理時間を変える命令ではないので、通信性能の改善とは別に考えます。
