概念と内部の仕組み

メソッドはコードを短くまとめるだけの機能ではありません。入力・出力・副作用の境界を決める道具です。C#のrefとoutを「参照型ならref」と誤解しないよう、変数への代入とオブジェクトの変更を分けて学びます。

入力と出力を先に決める

メソッドは引数を受け取り、処理し、戻り値を返します。int Add(int a, int b)なら、2つのintを受け取りintを返します。Consoleへの表示まで混ぜず、計算だけを返す形にすると単体テストがしやすくなります。C#では公開メソッド名をPascalCaseにする慣習があります。

省略できる引数

int Add(int value, int step = 1)のように既定値を設定できます。Add(5)ならstepは1です。Add(value: 5, step: 3)のような名前付き引数は、同じ型の引数が続くときに意図を示します。ただし引数名の変更が呼び出し側へ影響するため、公開APIでは名前も契約として扱います。

参照型の引数も通常は値渡し

通常の引数は値渡しです。classを渡す場合も「参照の値」をコピーしています。参照先のプロパティ変更は見えますが、メソッド内で引数を別オブジェクトへ再代入しても呼び出し元の変数は差し替わりません。refは変数そのものを参照渡しし、outはメソッド側が値を設定して返す用途です。ref/outを増やす前に戻り値やタプルで表せないか考えます。

メソッドの契約を入力と出力で読む

decimal Subtotal(decimal price, int quantity)は、価格と個数を受け取りdecimalの小計を返す契約です。メソッド名、パラメーター、戻り値を見るだけで、呼び出し側が何を準備し何を受け取るか分かります。戻り値をConsole.WriteLineへ直接渡しても、計算と表示の責務は別です。

計算メソッドの中で勝手にReadLineする設計は、入力元をコンソールへ固定します。同じ計算をWeb APIやテストで使いたいなら、必要な値を引数で受け取り、結果を返す方が再利用しやすくなります。まずは戻り値で表せるものを戻り値で表し、呼び出し元の変数を変更するrefを不必要に増やさないようにします。

値渡しでは何のコピーを受け取るのか

C#の通常の引数は値渡しです。intを渡せば整数値のコピー、クラスの変数を渡せば参照のコピーです。後者は同じオブジェクトを指すため、メソッド内からプロパティを書き換えると呼び出し側にも見えます。しかしパラメーターへnewした別のオブジェクトを代入しても、呼び出し元の変数そのものは置き換わりません。

refは変数の格納場所を参照渡しすることを明示します。呼び出し側と宣言側の両方にrefを付け、呼び出し前に値を初期化します。intの更新や参照先の差し替えが呼び出し元へ伝わります。参照型と参照渡しは別の分類なので、クラスだからrefが必須という説明は正しくありません。

outとin、戻り値との使い分け

outはメソッドが結果を設定するための参照パラメーターです。呼び出し前の初期値は不要ですが、メソッドが正常に戻るすべての経路で代入しなければなりません。TryParseはboolで成功を返し、outで解析値を返すため、この二つを組み合わせています。out var resultと書くこともできますが、失敗時に何を設定するかはメソッドの契約です。

inは読み取り専用の参照として渡すための修飾子です。大きな値型のコピーを避けたい場面などで検討しますが、初学段階で高速化のために何でもinへ変更する必要はありません。複数の結果を返すならタプルや専用の結果型も候補です。APIを利用する側が、入力なのか出力なのかを読み取れることが先です。

オーバーロード・名前付き引数・既定値

同名でもパラメーターの型や個数が異なるメソッドはオーバーロードできます。戻り値の型だけを変えても区別できません。呼び出し時には引数の型に基づいて適切な候補が解決されるため、数値リテラルの型や暗黙変換が影響します。曖昧な呼び出しになったら、型を明示して意図を示すのが調査の入口です。

名前付き引数はprice:500m, quantity:3のように値の意味を示します。boolの引数が複数ある場合にも読みやすくなります。省略可能な引数の既定値は通常コンパイル時定数で、呼び出し側のコンパイル時に使われることがあります。公開ライブラリで既定値を変えても古い利用側が自動的に新しい値へ変わると期待せず、API互換性を考えます。

概念をもう一段掘り下げる

メソッドは入力・処理・結果に名前を付ける

メソッドは、何度も使う手順や一つの役割に名前を付けた処理です。合計の計算を三か所へコピーすると、仕様変更時に三か所を同じように直す必要があります。メソッドへまとめると呼び出し側は目的を名前で読み、実装は一か所へ集められます。ただし、何でも大きな共通処理へ詰め込むと逆に理解しにくくなるため、入力と出力を説明できる単位にします。

引数は呼び出しで渡す値、パラメーターは定義側でその値を受け取る変数です。戻り値は処理の結果として呼び出し側へ返す値です。たとえばCalculateTotal(120, 3)の120と3が引数、定義にあるunitPriceとquantityがパラメーター、360が戻り値になります。

構文を一つずつ読む

C# · 独立したコード例
int result = CalculateTotal(120, 3);
Console.WriteLine(result);

static int CalculateTotal(int unitPrice, int quantity)
{
    int total = unitPrice * quantity;
    return total;
}

期待出力は360です。static int CalculateTotalのintは戻り値の型です。かっこ内の二つのintは受け取る値の型です。return total;はtotalを結果として返し、メソッドの処理を終えます。ここで定義しているのはトップレベル文から呼べるstaticローカル関数です。型に属するメソッドにも、引数と戻り値の考え方は共通です。

順序 実行する場所 状態
① 呼び出し側 引数120と3を用意
② CalculateTotalに入る unitPrice=120, quantity=3
③ メソッド内 total=360
④ return 360を呼び出し側へ返す
⑤ 呼び出し側 result=360として受け取る
⑥ 表示 360

メソッド内のtotalと呼び出し側のresultは別の変数です。同じ名前にしても自動的に共有されるわけではありません。スコープとは名前を使える範囲です。メソッドのパラメーターとローカル変数はそのメソッドの中で利用し、外から直接名前で読むことはできません。

よくある間違いと修正

よくある間違い

トップレベルの下に置くstatic関数はローカル関数です。クラスのメソッドと記述場所は異なりますが、引数・戻り値を考える基本は同じです。

intを渡して増やしたのに元が変わらない

修正箇所: 更新メソッドと呼び出し側の代入

修正前

csharp
int count = 1;
Increment(count);
Console.WriteLine(count);
static void Increment(int value) { value++; }

修正後

csharp
int count = 1;
count = Increment(count);
Console.WriteLine(count);
static int Increment(int value) => value + 1;
変更理由

更新結果を戻り値として返し、呼び出し側で代入します。refでも実現できますが、単純な計算では入力と戻り値で表すと、副作用が少なくテストしやすい形になります。

修正後の確認

  • 1が2になる
  • 0が1になる
  • 呼び出し後の代入を外すと元は変わらない

標準：名前付き引数で注文金額を計算する

価格と個数に送料を加えた合計を返すTotalを作ります。quantityの既定値は1、shippingは0m。価格500・個数3・送料200を名前付き引数で渡し1700を表示します。

  • 金額の戻り値はdecimal
  • 省略可能引数は必須引数の後ろへ置く
  • メソッド内で表示せず合計を返す
開始コード
csharp
// 標準：名前付き引数で注文金額を計算する
// 課題とテストケースを読んで、自分で実装してください。

入力例・前提条件

price=500m、quantity=3、shipping=200m。省略時の個数1、送料0m。

考え方のヒント

price*quantityを求めてからshippingを一度だけ足す。名前付き引数を宣言名に合わせる。

入力するとlocalStorageへ保存実行・自動採点は行いません
解答例と確認ポイント
csharp
decimal result = Total(price: 500m, quantity: 3, shipping: 200m);
Console.WriteLine(result);
Console.WriteLine(Total(500m));
static decimal Total(decimal price, int quantity = 1, decimal shipping = 0m)
    => price * quantity + shipping;

想定出力

1700 500
  • 名前付き引数は、同じような数値が並んでも価格・個数・送料を読み分けやすくする。
  • 2回目はquantity=1、shipping=0が使われる。
  • この例は有効な固定値の計算に絞っている。業務用へ広げる場合は負数や上限の契約を追加する。
入力 / 条件期待結果
500・3・2001700
500だけ500
0・1・00

処理と結果の読み解き

小計1500に送料200を足して1700。送料を個数分掛けないこと、名前付きでも各値が正しいパラメーターへ対応することを確認する。

よくある別解と選び方

位置引数でも同じ計算はできるが、今回の要件は名前付き。全引数を明示すると意味を読み取りやすい。

よくある間違いと確認箇所

引数の名前を呼び出し元の変数名だと考えない。メソッド宣言のパラメーター名を使う。

実務へのつながり：数値引数が多い処理では、どの値を渡しているかがレビューで分かる呼び出しにする。

応用

応用：成功時だけ使えるTryメソッド

TryGetPercentage(int value,int total,out decimal percentage)を作り、total<=0、value<0、value>totalならfalse、それ以外なら百分率を設定してtrueを返します。失敗時のpercentageは0にします。

  • outへまず0を代入すれば失敗経路でも値が定まる
  • 割り算の前に条件を検証する
  • 成功時だけ計算しtrueを返す
開始コード
csharp
// 応用：成功時だけ使えるTryメソッド
// 課題とテストケースを読んで、自分で実装してください。

入力例・前提条件

valueとtotal。total<=0、value<0、value>totalは拒否し、失敗時percentage=0。

考え方のヒント

outへ0を設定してから早期returnすると、全ての正常に戻る経路の代入を揃えやすい。

入力するとlocalStorageへ保存実行・自動採点は行いません
解答例と確認ポイント
csharp
bool ok = TryGetPercentage(3, 4, out decimal result);
Console.WriteLine($"{ok}: {result.ToString("0.##", System.Globalization.CultureInfo.InvariantCulture)}");
Console.WriteLine(TryGetPercentage(1, 0, out _));
static bool TryGetPercentage(int value, int total, out decimal percentage)
{
    percentage = 0m;
    if (total <= 0 || value < 0 || value > total) return false;
    percentage = (decimal)value / total * 100m;
    return true;
}

想定出力

True: 75 False
  • outは失敗経路を含め正常復帰前の代入が必要なので、最初に既定値を設定する。
  • total=0を計算前に除外して、ゼロ除算を避ける。
  • 呼び出し側はboolを判定してから百分率を使う。false時の0を正常な0%と誤認しない。
入力 / 条件期待結果
3/4true・75%
0/4true・0%
1/0false・結果0

処理と結果の読み解き

不正条件を先に排除し、totalが正と確定した後でdecimalへ変換して百分率を計算する。戻り値boolは成否、outは結果という二つの契約。

よくある別解と選び方

成否と結果をタプルやrecordで返す設計は後で比較できる。ここではoutの代入保証を学ぶ。

よくある間違いと確認箇所

一つの失敗経路でoutを設定しないとコンパイルできない。value=0,total>0は有効な0%であり、失敗とは異なる。

実務へのつながり：Try系のAPIでは、値だけで成否を判断せず戻り値の契約を守る。

確認問題

Q1. 通常のclass型の引数を渡すとき、コピーされるのは？
正解：同じ参照先を指す値がコピーされます。

呼び出し元と引数の変数は別ですが、同じ実体を指す参照値を持ちます。メソッド内でプロパティを変更すれば共有する実体が変わります。

解説：通常の引数渡しは深いコピーではありません。

newして全ての子オブジェクトまで複製する処理は自動で行われません。独立したデータが必要ならコピーの深さを設計して明示します。

解説：変数への参照渡しはrefなどを明示する場合です。

通常の値渡しでは、引数の変数へ別のnewを代入しても呼び出し元の変数は付け替わりません。refは変数自体へのアクセスを渡す別の指定です。

解説：引数には値が渡ります。

渡るのは参照型の値である参照です。値型でないから何もコピーされない、という理解ではオブジェクト共有を説明できません。

Q2. out引数について正しい説明は？
解説：outでは呼び出し前の初期化は不要です。refとは条件が異なります。

出力を受け取る場所として渡すので、事前に値が入っている必要はありません。refは入力にも使うため事前の代入が必要になります。

正解：outは出力用引数です。通常終了の経路で代入が必要です。

boolで失敗を返す経路でも、正常にreturnするならoutへの代入が必要です。例外で終了する経路と通常の戻りを区別します。

解説：書き込み先になる変数を渡します。

定数は書き戻す先になりません。out int valueのように、メソッドが結果を書き込める変数を指定します。

解説：outは例外宣言ではなく、メソッドから値を書き戻すための引数修飾子です。

例外の種類を型宣言へ列挙する指定ではありません。TryParseのboolとout intのように、成否と変換値を別に返す場面に使います。

Q3. 通常の引数でクラスの変数を渡した場合は？
解説：refは明示的な別の引数渡し方法です。

class型であることとref修飾子は別の軸です。通常は参照値の値渡しで、refを明示したときだけ変数への参照渡しになります。

解説：一般の値渡しは参照先全体の複製を意味しません。

オブジェクトを新規に作らないため、参照先の子データも自動複製されません。変更がどこへ見えるかは共有している実体を図にして考えます。

正解：同じオブジェクトを指す参照値をコピーして渡します。

引数の受け取り用変数に、同じ実体を指す値を保存します。その変数の再代入と、参照先の状態変更の違いを説明できることが重要です。

解説：参照先に変更可能なプロパティがあれば同じ実体を変更できます。

public setのプロパティなど変更可能な操作は呼べます。値渡しは参照先を読み取り専用にする指定ではありません。

Q4. outパラメーターについて必要な条件は？
正解：コンパイラーが代入済みか確認するため、失敗を返す経路にも代入が必要です。

trueで終わる経路だけ代入し、falseでそのまま戻るコードは条件を満たしません。呼び出し後にout変数が代入済みと扱える理由です。

解説：呼び出し前の初期化が必要なのは通常のrefとの重要な違いです。

outは未代入の変数を出力先にできます。同じ見た目の引数でもrefとoutでは呼び出す前後の責任が違います。

解説：成功判定と出力値は別の結果であり、値の種類も異なります。

boolは成功かどうか、out intは解析した整数など役割が違います。たとえば成功trueで結果0も、失敗falseで結果0もあり得ます。

解説：intやdecimalなどの値型にも利用できます。

TryParseでout intを使うのが具体例です。値型か参照型かではなく、メソッドから値を書き戻す必要があるかで使います。

Q5. 戻り値だけ異なるint Get()とstring Get()を同じ型に定義できますか？
解説：呼び出しの引数から候補を区別できないため、この形は認められません。

引数なしのGet()という呼び出しだけでは二つを区別できません。受け取り側の型だけを頼りに同名同引数を宣言することは認められません。

正解：オーバーロードはパラメーターの型や個数などで区別します。

Get(int id)とGet(string name)のように入力の形を変えて区別します。戻り値だけを変えたいなら別のメソッド名などを検討します。

解説：識別子の表記とオーバーロードの規則は別です。

大文字・小文字は名前を識別する要素ですが、同じ名前で戻り値だけ違う宣言の規則を変更しません。表記上の慣習とは別です。

解説：受け取り側をvarにしても宣言の重複は解消しません。

varは初期化式から型を推論する側です。重複したメソッド宣言を有効にする仕組みではないため、呼び出し側では解決しません。

理解チェックと公式資料

  • 入力・戻り値・副作用を区別してメソッドを設計できる
  • 参照型の値渡しとrefの違いを説明できる
  • outの失敗経路でも値を設定できる
  • 既定引数と名前付き引数を読み分けられる
