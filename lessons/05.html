概念と内部の仕組み

C#のswitch式とパターンは「条件に応じて値を作る」という設計に向いています。条件が重なるときの順序、範囲外の入力、複数条件の組み合わせを扱い、通るべき経路をテストできる形にします。

ifは馴染みのある形

if、else if、elseは上から順に条件を評価し、最初にtrueになった分岐だけを実行します。条件にはboolを使います。条件が重なる場合は、より限定された条件を先に置きます。たとえば90点以上を判定する前に60点以上を置くと、95点も60点以上の分岐に入ります。

switch式は値を返す

C#のswitch式では、入力値 switch { 条件 => 値, ... } と書きます。各分岐が値を返すので、結果を変数へ代入できます。>= 80は関係パターン、_は残りすべてに対応するパターンです。単純な値の分類に向き、複数の副作用を詰め込む場所には向きません。

範囲外も設計する

条件分岐には正常値だけでなく、0、境界の直前・直後、負数、想定上限超過を通してみます。テストでは59/60、79/80などが重要です。C#の通常のswitch文では、非空のcaseから次のcaseへ暗黙に処理が流れ落ちる書き方はできないため、各分岐の終端を明確にします。

文と式の違いからifとswitchを選ぶ

文は処理を実行する単位、式は評価すると値になる単位です。if文は条件に応じて複数の処理を実行したい場面で自然です。switch式は入力に応じてラベルや料金など一つの値を選ぶ場面に向きます。どちらでも書ける処理については、読み手が目的を短く追える方を選びます。

score switch { >= 60 => "合格", _ => "不合格" }は一つのstring値になります。各アームの結果が最終的な型へ揃う必要があります。switch式に必ず長いメソッド呼び出しや副作用を詰め込むのではなく、値の選択と保存や通知のような処理は分けると、検証しやすくなります。

上から最初に一致する条件が選ばれる

switch式は上からパターンを評価して最初に一致したアームを選びます。80点以上と60点以上は重なるため、狭い条件の80点以上を先に置きます。>= 60を先に置いてから>= 80を置けば、後者は既に前の条件で覆われて到達できず、コンパイラーが検出する場合があります。

入力の有効範囲が0〜100なら、最初に< 0 or > 100を処理しておくと残りの分岐が読みやすくなります。_は残ったどの値にも一致する破棄パターンです。何でも_で成功扱いにするのではなく、残りが「有効な最低ランク」なのか「想定外」なのかを説明できるようにします。

関係・論理・型・プロパティのパターン

>= 60は関係パターン、>= 0 and <= 100は論理パターンを組み合わせた範囲判定です。条件式の&&や||とは構文の場所が異なり、score is >= 0 and <= 100のように値に対して適用します。条件を長くつなぐときは括弧や分割を使い、優先順位だけに読解を頼らないようにします。

value is string textなら、値がnullではないstringのときだけtextとして取り出せます。プロパティパターンはcustomer is { IsActive: true }のように型の内部の値を条件として表せます。whenはパターンに追加条件を付けるガードです。すべての機能を使うことが目的ではなく、null判定やキャストを重複させずに安全に条件を記述する道具として理解します。

境界値を先に一覧にしてから実装する

条件分岐のバグは80点が上位に入らない、18歳がどこにも入らない、といった境界で現れがちです。年齢区分なら-1、0、12、13、17、18を表にして期待するラベルを書いてから実装します。正常な代表値一つだけで動作確認を終えないようにします。

入力が範囲外の場合に例外にするか、エラーの値を返すかも仕様です。UIの入力エラーを通常の分岐として返す場面と、内部メソッドへあり得ない値が渡された契約違反では扱いが変わります。また条件の中でカウンターを増やすなどの副作用を入れると、短絡評価で実行回数が変わるため、判定と更新を分離するのが基本です。

概念をもう一段掘り下げる

条件分岐は「今の状態から、次の処理を選ぶ」

条件分岐は、条件式の結果に応じて実行する処理を選ぶ仕組みです。条件式はtrueまたはfalseの値を作る式です。たとえばstock > 0は在庫が正ならtrueになります。分岐がなければ、在庫0でも購入処理へ進むなど、異なる状態へ同じ処理を適用してしまいます。

boolはtrueとfalseを扱う型です。「0なら偽、その他なら真」という暗黙の読み替えをC#のifは行いません。if (stock)ではなく、if (stock > 0)のように判断を明示します。何を真とするのかを条件式へ書くことで、境界の値や業務ルールをレビューできます。

if・else if・elseが連なっている場合は、上から条件を調べ、最初にtrueになった一つの枝へ進みます。一方、独立したifを複数書くと、それぞれの条件を別々に検査します。この違いを理解しないと、複数の料金区分を表示したり、同じ値へ二重に割引したりする問題が起こります。

文法と最小例

C# · 独立したコード例
int score = 80;
if (score >= 80)
{
    Console.WriteLine("合格・優秀");
}
else if (score >= 60)
{
    Console.WriteLine("合格");
}
else
{
    Console.WriteLine("再挑戦");
}
Console.WriteLine("判定終了");

期待出力は「合格・優秀」、次の行に「判定終了」です。かっこ内が条件式、{}内が条件に対応する文のまとまりです。このまとまりをブロックと呼びます。今回は80が最初の条件を満たすため、60以上かどうかの二つ目の条件は評価しません。

段階 調べること 結果 次の動き
① scoreを80で初期化 score=80 最初のifへ
② 80 >= 80 true 最初のブロックへ
③ 表示 合格・優秀 else ifとelseを飛ばす
④ 分岐の後の文 判定終了 終了

分岐の内部ではscoreを書き換えていないため、処理の前後でscoreは80のままです。「条件を調べること」と「状態を変更すること」を分けて読むと追跡しやすくなります。コンパイラーはブロックや条件をIL上の制御の流れへ変換し、実行時には選ばれた経路の処理が進みます。ソースの全ブロックを毎回実行してから不要な結果を捨てるわけではありません。

文法・実例・処理順

csharp
int score = 82;
string result = score switch
{
    < 0 or > 100 => "範囲外",
    >= 80 => "よくできました",
    >= 60 => "合格",
    _ => "再学習"
};
Console.WriteLine(result);

想定出力

よくできました

処理順

  1. 82は0〜100の範囲内なので最初の条件を通らない。
  2. >= 80に一致し、対応する文字列が選ばれる。
  3. それより下の条件は選ばれず、resultを表示する。

値・状態の変化を追う

送料の分岐を境界値で追う

csharp
int[] amounts = { -1, 0, 2999, 3000, 5000 };
foreach (int amount in amounts)
{
    string shipping = amount switch
    {
        < 0 => "不正",
        >= 3000 => "無料",
        _ => "300円"
    };
    Console.WriteLine($"{amount}: {shipping}");
}

出力

-1: 不正 0: 300円 2999: 300円 3000: 無料 5000: 無料
段階値・状態読み解き
-1最初の< 0が一致後の無料条件や通常送料は評価対象にならない
0どちらの条件にも一致せず_へ0は有効だが無料条件を満たさない
2999_へ境界の直前は300円
3000>= 3000が一致境界を無料へ含める
5000>= 3000が一致値が大きくても同じ区分

よくある間違いと修正

よくある間違い

最終の_を省略すると、入力によっては一致する分岐がなく実行時例外になることがあります。入力範囲を設計し、未対応ケースの警告を無視しないでください。

境界の60点だけ不合格になる

修正箇所: 合否を返すswitch式の関係演算子

修正前

csharp
int score = 60;
string result = score switch { > 60 => "合格", _ => "不合格" };
Console.WriteLine(result);

修正後

csharp
int score = 60;
string result = score switch { >= 60 => "合格", _ => "不合格" };
Console.WriteLine(result);
変更理由

合格条件が「60以上」なので、等号を含む>=へ変更します。>と>=の差を通常の80点では検出できないため、59・60・61の三点で確認します。

修正後の確認

  • 59→不合格
  • 60→合格
  • 61→合格

応用

応用：型と値で入力を分類する

object?の配列{null, 3, -1, "C#", ""}を、なし・正整数・その他整数・文字あり・空文字に分類してください。型パターンで取り出した値を使います。

  • nullを最初に処理する
  • int n when n > 0の後にintの残りを扱う
  • stringのLengthで空文字か分ける
開始コード
csharp
// 応用：型と値で入力を分類する
// 課題とテストケースを読んで、自分で実装してください。

入力例・前提条件

null、3、-1、C#、空文字をobject?として順に扱う。

考え方のヒント

最初に型を調べ、その型として取り出した値に追加条件を付ける。

入力するとlocalStorageへ保存実行・自動採点は行いません
解答例と確認ポイント
csharp
object?[] values = { null, 3, -1, "C#", "" };
foreach (object? value in values)
{
    string label = value switch
    {
        null => "なし",
        int n when n > 0 => "正整数",
        int => "その他整数",
        string s when s.Length > 0 => "文字あり",
        string => "空文字",
        _ => "未対応"
    };
    Console.WriteLine(label);
}

想定出力

なし 正整数 その他整数 文字あり 空文字
  • intパターンが成立したときだけnとして数値比較するので、文字列への不正なキャストを行わない。
  • 空文字もstringなので、文字ありの条件に一致しなかったstringとして扱える。
  • doubleなどは最後の未対応に入り、想定外の型を成功扱いにしない。
入力 / 条件期待結果
nullなし
0その他整数
3.5未対応

処理と結果の読み解き

nullは値がない。intなら正かどうか、stringなら文字数が0かどうかを調べる。型を確かめずLengthや大小比較を使えない理由が分かる。

よくある別解と選び方

switch文で分岐ごとに表示することもできる。結果文字列を返すならswitch式としてまとめやすい。

よくある間違いと確認箇所

objectだから全ての型のメンバーを直接呼べると考えない。型パターンで安全に取り出した変数を使う。

実務へのつながり：異なる形の入力を扱う境界では、型の判定と値の条件を段階的に検証する。

確認問題

Q1. switch式の _ => "その他" は何を表す？
正解：最後の受け皿として使う破棄パターンです。

_はこのswitch式で残った全ての値に一致する受け皿です。狭い条件を上に置き、最後に既定の値を返す順序で使います。

解説：この分岐は文字列を返します。

このアームの右辺は"その他"という文字列です。例外を投げるならthrow式を明示する必要があり、_自体にその意味はありません。

解説：この文脈では変数代入ではありません。

この位置の_は破棄パターンです。値を保存して後から使う変数を宣言しているわけではないので、代入先として読みません。

解説：switch式はループではありません。

switch式は値を選ぶ式です。繰り返しの終了を指示するbreakや、周回を飛ばすcontinueとは目的が違います。

Q2. 82点をif / else ifで判定するとき、80点以上より先に60点以上を調べるとどうなる？
解説：最も厳しい条件を自動選択する仕組みではありません。

if/else ifは上から順に条件を確認します。条件の厳しさを比較して最適な一つを自動選択する機能ではありません。

正解：if / else ifは最初にtrueになった分岐を通ります。switch式の包含されたパターンとは異なり、不適切な条件順が必ずコンパイルエラーになるわけではありません。

82は最初の82>=60でtrueになるため、その分岐を通ります。switch式で後続パターンを完全に覆う並びなら、到達不能としてビルド時に検出される場合もあります。

解説：1つの値だけを選びます。

if/else ifやswitch式は、この形では選んだ一つの分岐を使います。別々の独立したifを並べた場合とは制御の構造が異なります。

解説：条件順で決定します。

判断は条件と記述順から追えます。入力82を各条件へ当てはめ、最初にtrueとなる位置を探すのが具体的な確認方法です。

Q3. 0〜100の点数で80以上をA、60以上をB、それ以外をCにするとき、switch式の並びは？
正解：狭い条件を先に評価すると80以上がAへ入ります。

まず80以上を取り出すので、残りの60以上は60〜79です。広い条件から先に取るとこの区別ができません。

解説：先頭の_がすべてに一致し、後ろのアームが不要になります。

_は80以上も60以上も含みます。先頭に置くと後の条件まで到達できないため、受け皿は最後に置きます。

解説：先の>=60に80以上も含まれ、後の条件へ到達できません。

80以上は60以上の一部なので、先の条件が後の条件を覆います。狭い条件を先に並べる理由は集合としての含み方にあります。

解説：switch式は最初に一致するアームを選ぶため順序が重要です。

同じ条件でも順序で選ばれる結果が変わります。ifやswitchを読むときは、条件だけでなく上からの流れも仕様の一部として扱います。

Q4. value is string textがtrueのとき保証されることは？
解説：文字列かどうかと数値形式かどうかは別条件です。

"abc"もstringなので型パターンに一致します。数値へ変換できるかはint.TryParseなどで追加確認する必要があります。

解説：パターン変数を導入するのであり、元の宣言型を書き換えるわけではありません。

元の変数の宣言型が書き換わるのではありません。条件が成立する範囲でstringとして扱えるtextという名前を導入します。

解説：空文字や空白文字列もstringなので、内容は別に検証します。

空文字""も長さ0の有効なstringです。型の確認で空白や業務上の必須条件まで満たしたと考えないでください。

正解：型パターンはnullには一致せず、変数textをstringとして取り出します。

nullは型パターンに一致しません。true側ではtext.Lengthなどを使えますが、内容の妥当性は別の規則で確認します。

Q5. 18歳以上の条件を検証する入力として最も有効な組み合わせは？
解説：同じ入力の反復だけでは境界の両側を比較できません。

18だけでは>18と>=18の差は一部見えますが、周辺の誤った条件を十分に比較できません。異なる入力で境界の両側を確かめます。

正解：境界直前・境界・直後で分岐の含まれ方を確認できます。

17は対象外、18と19は対象です。この三つで等号の有無や閾値のずれを具体的に検出しやすくなります。

解説：通常の大人の値だけでは等号の誤りを見逃します。

30は>18でも>=18でもtrueです。一般的な正常値だけを選ぶと、ちょうど18の扱いを誤っていても見逃します。

解説：境界から離れた一件では18の扱いを確認できません。

100は境界から離れているので多くの誤った条件でも通ります。代表値に加えて、条件が切り替わる直前・当日・直後を試します。

理解チェックと公式資料

  • 値を返すswitch式と処理を分けるif文を選べる
  • 最初に一致するアームの規則を説明できる
  • 型パターン後の変数を安全に使える
  • 仕様から境界値を列挙できる
